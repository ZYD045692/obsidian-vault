# 6.6 本章小结及疑难点

> [!abstract] 一句话总结
> 本节通过端口机制、网络层级辨析、TCP 拥塞控制对 HTTP 性能的影响及主机启动全流程，串联应用层至链路层的核心交互逻辑。

## 核心要点
### 考点1：客户与服务器端口号机制
**服务器使用固定公开的熟知端口，客户使用操作系统自动分配的临时端口，两者组合唯一标识端到端连接。**
连接标识 = (服务器熟知端口，客户临时端口)

> [!tip] 考试怎么用
> 注意区分端口性质：服务器端口固定，客户端口动态且仅本次通信有效。

### 考点2：互联网与万维网的区别
**互联网是提供主机连通性的全球网络互联系统，万维网是构建其上基于 HTTP 的应用层生态。**
互联网 (Internet) \to TCP/IP 协议族，主机连通性；万维网 (WWW) \to HTTP 协议，网页链接

> [!tip] 考试怎么用
> 比喻记忆：互联网是“路”，万维网是“路上跑的一种车”，勿混淆层级。

### 考点3：HTTP/1.1 持续连接与 RTT 计算
**即使使用持续连接，受 TCP 初始拥塞窗口 (1MSS) 限制，传输大对象仍需多个 RTT 分批次发送。**
RTT_1: 握手前两次; RTT_2: 握手 + 请求 +1MSS; RTT_3: ACK+ 请求 +2MSS; RTT_4: ACK+ 剩余数据

> [!tip] 考试怎么用
> 易错点：忽略传输层拥塞控制，误以为带宽充足即可一次性发送，必须按 cwnd 增长节奏计算。

### 考点4：主机开机访问 Web 站点全流程
**主机需依次经历 DHCP 获取配置、DNS 解析域名、ARP 解析 MAC、HTTP 请求资源及 TCP 连接释放过程。**
1.DHCP(UDP/IP/MAC) \to 2.DNS(UDP/IP/MAC) \to 3.HTTP(TCP/IP/MAC) \to 4.TCP 挥手

> [!tip] 考试怎么用
> 注意封装层次：DHCP/DNS 报文均封装在 UDP 中，再封装 IP，最后封装以太网帧；现代交换以太网不用 CSMA/CD。

## 易混与对比
**互联网 vs 万维网**

|特征|互联网 (Internet)|万维网 (WWW)|
|---|---|---|
|本质|全球计算机网络互联系统|构建在互联网上的应用层生态|
|核心功能|提供主机之间的连通性|提供相互链接的网页和网站访问|
|基础协议|TCP/IP 协议族|HTTP 协议|
|比喻|“路”|“路上跑的一种车”|

- **DHCP 与 DNS 的传输层协议**：两者均属于应用层协议，且报文都封装在 **UDP** 数据报中，再封装进 IP 数据报，最后由数据链路层封装为以太网帧传输。切勿误认为 DNS 或 DHCP 直接使用 TCP 或无传输层。
- **CSMA/CD 的适用场景**：传统共享式以太网需遵循 CSMA/CD 机制避免冲突；但现代交换式以太网普遍采用全双工模式，**不再使用** CSMA/CD。做题时需根据题目描述的以太网类型判断。

## 闪卡
#card
- 服务器进程使用何种端口号？::熟知端口号，固定且公开。
- 客户进程端口号如何分配？::由操作系统在连接发起时自动分配。
- 客户临时端口号的有效范围？::仅在本次通信中有效。
- 服务器如何建立唯一的端到端连接？::通过自身熟知端口与客户临时端口的一对组合。
- 互联网的通信基础协议族是什么？::TCP/IP 协议族。
- 万维网通过什么协议和工具访问？::HTTP 协议和浏览器。
- 互联网起源于哪个网络？::ARPAnet。
- 万维网的组成元素是什么？::相互链接的网页和网站。
- TCP 连接初始拥塞窗口通常为多少？::1MSS。
- 第 2 个 RTT 服务器能发送多少数据？::1MSS（此时 cwnd=1）。
- 第 3 个 RTT 拥塞窗口增至多少？::2MSS。
- 为何带宽充足仍需 4 个 RTT？::受限于拥塞窗口增长节奏，无法一次性发送全部数据。
- 主机开机首先通过什么协议获取 IP？::DHCP 协议。
- DHCP 报文在传输层使用什么协议？::UDP。
- 若 DNS 服务器在不同子网，ARP 解析谁？::解析默认网关的 MAC 地址。
- 现代交换式以太网是否使用 CSMA/CD？::否，普遍采用全双工模式，不再使用。
- TCP 连接在何时释放？::所有资源传输完成后，通过四次挥手释放。
