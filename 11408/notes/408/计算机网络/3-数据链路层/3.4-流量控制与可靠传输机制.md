# 3.4 流量控制与可靠传输机制

> [!abstract] 一句话总结
> 流量控制通过滑动窗口匹配收发速率，可靠传输利用 ARQ 机制（确认 + 超时/NAK）应对丢包错包，三者（S-W, GBN, SR）在窗口大小与重传策略上权衡效率与复杂度。

## 核心要点
### 考点1：流量控制与滑动窗口机制
**流量控制由接收方控制发送方速率，数据链路层通过不返回确认帧实现，传输层通过动态调整窗口字段实现。**
停止 - 等待：$W_T=1, W_R=1$；后退 N 帧：$W_T>1, W_R=1$；选择重传：$W_T>1, W_R>1$。若 $n$ 比特编号，需满足 $W_T + W_R \leqslant 2^n$。

> [!tip] 考试怎么用
> 区分数据链路层（固定窗口、相邻节点）与传输层（动态窗口、端到端）的控制手段差异；注意 $W_R=1$ 保证有序接收。

### 考点2：停止 - 等待协议 (S-W)
**发送方每发一帧需等待确认，仅需 1 比特序号区分新旧帧，出错或丢失时超时重传，重复帧被丢弃并重发确认。**
序号空间：1 比特（0 和 1）。机制：发送缓存保留副本直至收到 ACK；接收方记录最近序号判重。

> [!tip] 考试怎么用
> 理解为何 1 比特足够（交替使用 0/1）；注意确认帧丢失会导致发送方重传，接收方需处理重复帧。

### 考点3：后退 N 帧协议 (GBN)
**发送方可连续发送窗口内帧，接收方仅按序接收（$W_R=1$），出错时重传该帧及之后所有已发未确认帧。**
累积确认：ACKn 表示 n 及之前全收到。窗口约束：$1 < W_T \leq 2^n - 1$。计时器：仅维护最早未确认帧的计时器。

> [!tip] 考试怎么用
> 核心考点是“后退 N 帧”含义（重传出错帧及其后所有帧）及累积确认机制；误码率高时性能可能不如 S-W。

### 考点4：选择重传协议 (SR)
**接收方可缓存失序正确帧，发送方仅重传出错/超时帧，需对每帧独立确认，支持 NAK 快速重传。**
窗口约束：$W_T + W_R \leqslant 2^n$ 且 $W_R \leq W_T$，常取 $W_R = W_T = 2^{n-1}$。机制：每帧独立计时器，接收方缓存失序帧。

> [!tip] 考试怎么用
> 重点掌握窗口大小约束推导（防新旧帧重叠）；注意 SR 比 GBN 复杂但误码率高时效率更优。

### 考点5：信道利用率分析
**S-W 利用率极低（$U=T_D/(T_D+RTT)$），连续 ARQ 通过流水线提升利用率，无差错且窗口足够大时可达 1。**
S-W: $U=\frac{T_{\mathrm{D}}}{T_{\mathrm{D}}+\mathrm{RTT}+T_{\mathrm{A}}}$。连续 ARQ: 若 $NT_D \geq T_D+RTT+T_A$，则 $U=1$；否则 $U=\frac{NT_D}{T_D+RTT+T_A}$。

> [!tip] 考试怎么用
> 计算题高频点：注意区分 $NT_D$ 与往返时间的关系；误码率高时 GBN 实际利用率可能低于 S-W。

## 易混与对比
**三种 ARQ 协议核心机制对比**

|特性|停止 - 等待 (S-W)|后退 N 帧 (GBN)|选择重传 (SR)|
|---|---|---|---|
|发送窗口 $W_T$|1|$>1$ ($\leq 2^n-1$)|$>1$ ($\leq 2^{n-1}$)|
|接收窗口 $W_R$|1|1|$>1$ ($\leq 2^{n-1}$)|
|确认方式|逐个确认|累积确认 (ACKn)|逐个确认|
|重传策略|重传当前帧|重传出错帧及之后所有帧|仅重传出错/超时帧|
|接收行为|按序接收|按序接收，丢弃失序帧|缓存失序帧，按序交付|
|适用场景|简单、低延迟链路|低误码率链路|高误码率链路|

- **滑动窗口大小约束差异**：GBN 协议要求 $W_T \leq 2^n - 1$（因 $W_R=1$），而 SR 协议要求 $W_T + W_R \leq 2^n$ 且通常 $W_T=W_R=2^{n-1}$。若 SR 不满足此条件，接收窗口滑动后可能无法区分重传的旧帧与新发送的同序号帧。
- **确认帧丢失的处理**：S-W 和 SR 中，确认帧丢失导致发送方超时重传，接收方收到重复帧后丢弃并重发确认；GBN 中，接收方可重复发送最近一次确认（如 ACK1）促使发送方更新窗口，避免不必要的重传。

- 接收窗口大小为 1 时对帧接收顺序有何影响？::只有收到期望帧后才滑动窗口，保证帧严格按序接收。
- 停止 - 等待协议为何仅需 1 比特序号？::只需区分新帧与重传帧，交替使用 0 和 1 即可。
- 若确认帧丢失，发送方和接收方分别如何动作？::发送方超时重传；接收方丢弃重复帧并重发确认。
- 发送方何时清除发送缓存中的帧副本？::仅在收到该帧对应的确认帧后才清除。
- 停止 - 等待协议的主要缺点是什么？::信道利用率低，因每发一帧需等待确认。
- GBN 协议中接收窗口 $W_R$ 的大小是多少？::固定为 1，保证严格按序接收。
- GBN 的累积确认 ACKn 具体含义是什么？::表示 n 号帧及之前所有帧已正确接收，期望下一帧为 n+1。
- 若 2 号帧丢失，GBN 发送方需重传哪些帧？::重传 2 号帧及其后所有已发送但未被确认的帧。
- GBN 协议发送窗口 $W_T$ 的最大值是多少（n 比特编号）？::$2^n - 1$，防止序号回绕导致新旧帧混淆。
- SR 协议为何要求 $W_R + W_T \leqslant 2^n$？::防止接收窗口滑动后，重传旧序号帧与新帧混淆。
- SR 协议中接收方收到失序但正确的帧如何处理？::暂存到缓冲区，待缺失帧到达后按序交付上层。
- SR 协议如何触发重传（除超时外）？::接收方可发送否定帧 NAK 请求立即重传指定帧。
- SR 协议通常如何设置 $W_T$ 和 $W_R$（n 比特）？::常取 $W_T = W_R = 2^{n-1}$ 以充分利用序号空间。

- 连续 ARQ 协议在什么条件下信道利用率 U=1？::当 $NT_D \geq T_D+RTT+T_A$，即窗口足够大填满管道时。
- 若 RTT 远大于 $T_D$，哪种协议信道利用率最低？::停止 - 等待协议，因其大部分时间在等待。
- 信道平均数据传输速率如何计算？::信道利用率 × 信道带宽，或发送周期内数据量/发送周期。
