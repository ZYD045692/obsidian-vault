# 传输层

> [!abstract] 一句话总结
> 传输层通过端口实现进程间端到端逻辑通信，利用 TCP 的复杂机制（连接管理、滑动窗口、拥塞控制）在不可靠网络层之上构建可靠信道，或利用 UDP 提供低开销无连接服务。

## 核心考点
### 考点1：传输层服务与寻址
**传输层提供进程间逻辑通信，通过端口号实现复用分用，套接字唯一标识通信端点。**
套接字定义：$Socket = (IP 地址：端口号)$；端口号 16 位，范围 $0 \times 0000 \times FFFF$；熟知端口 $0 \times 1023$。

> [!tip] 考试怎么用
> 区分网络层主机通信与传输层进程通信；注意端口号仅具本地意义。

### 考点2：UDP 协议特性与首部
**UDP 是无连接、面向报文、尽最大努力交付的协议，首部仅 8 字节，支持多播。**
UDP 首部 4 字段：源端口、目的端口、长度、检验和；面向报文不拆分不合并；无拥塞控制。

> [!tip] 考试怎么用
> 牢记 UDP 首部 8B；理解面向报文与 TCP 面向字节流的区别；检验和含伪首部。

### 考点3：TCP 报文段结构
**TCP 首部最小 20 字节，通过序号、确认号及 6 个控制位实现可靠传输与连接管理。**
序号/确认号各 4B；数据偏移单位 4B；标志位：URG, ACK, PSH, RST, SYN, FIN；窗口字段 2B。

> [!tip] 考试怎么用
> 重点掌握 SYN/FIN/ACK 标志位组合含义；序号是对字节编号而非报文段。

### 考点4：TCP 连接管理（三次握手）
**采用三次握手建立连接，解决双方参数协商、资源分配及防止失效请求问题。**
状态流转：CLOSED -> LISTEN -> SYN-SENT -> SYN-RCVD -> ESTABLISHED；SYN 消耗序号。

> [!tip] 考试怎么用
> 理解为何需要三次而非两次（防止旧连接请求干扰）；SYN 报文不传数据但耗序号。

### 考点5：TCP 连接释放（四次挥手）
**采用四次挥手释放连接，主动关闭方需经历 TIME-WAIT 状态等待 2MSL。**
状态流转：FIN-WAIT-1 -> FIN-WAIT-2 -> TIME-WAIT (2MSL) -> CLOSED；FIN 消耗序号。

> [!tip] 考试怎么用
> 掌握 TIME-WAIT 两个作用（确保 ACK 到达、消除旧报文）；半关闭状态概念。

### 考点6：TCP 可靠传输机制
**通过序号、累积确认、超时重传及快速重传机制，保证数据无差错、不丢失、按序到达。**
超时重传基于 RTO；快速重传基于 3 个冗余 ACK；确认号为期望收到的下一个字节序号。

> [!tip] 考试怎么用
> 区分超时重传与快速重传触发条件；理解累积确认对失序报文的处理。

### 考点7：TCP 流量控制
**利用滑动窗口机制，由接收方通过 rwnd 控制发送方速率，防止接收缓存溢出。**
发送窗口上限 $= \min[rwnd, cwnd]$；零窗口时启动持续计时器发送探测报文。

> [!tip] 考试怎么用
> 区分流量控制（端到端，防溢出）与拥塞控制（全局，防过载）；零窗口死锁处理。

### 考点8：TCP 拥塞控制算法
**综合运用慢开始、拥塞避免、快重传、快恢复四种算法，动态调整 cwnd 适应网络负载。**
慢开始指数增 ($cwnd \times 2$)；拥塞避免线性增 ($cwnd + 1$)；超时则 $ssthresh=cwnd/2, cwnd=1$；3 冗余 ACK 则 $ssthresh=cwnd/2, cwnd=ssthresh$。

> [!tip] 考试怎么用
> 熟练绘制 cwnd 变化图；区分超时与 3 冗余 ACK 的不同处理策略（乘法减小细节）。

### 考点9：MSS 与重传策略辨析
**MSS 决定不分片最大数据长度；TCP 重传机制介于 GBN 与 SR 之间，支持 SACK。**
MSS 过大导致 IP 分片，过小降低效率；TCP 默认重传丢失段，SACK 可选支持选择性重传。

> [!tip] 考试怎么用
> 理解 MSS 与 MTU 关系；辨析 TCP 重传是 GBN 还是 SR（混合体）。

## 易混与对比
**流量控制 vs 拥塞控制**

|特性|流量控制 (Flow Control)|拥塞控制 (Congestion Control)|
|:---|:---|:---|
|**控制对象**|点对点（发送方与接收方）|全局（发送方与整个网络）|
|**目的**|防止接收方缓存溢出|防止网络链路过载|
|**依据**|接收方通告的接收窗口 (rwnd)|网络拥塞程度推断的拥塞窗口 (cwnd)|
|**实施者**|接收方主导，发送方执行|发送方自主调整|
|**窗口决定**|取决于接收方处理能力|取决于网络当前负载状况|

**TCP vs UDP 核心差异**

|特性|TCP|UDP|
|:---|:---|:---|
|**连接性**|面向连接（三次握手）|无连接|
|**可靠性**|可靠交付（确认、重传、排序）|尽最大努力交付，不保证可靠|
|**数据单位**|面向字节流（无边界）|面向报文（保留边界）|
|**拥塞控制**|有（慢开始、拥塞避免等）|无|
|**首部开销**|最小 20 字节|固定 8 字节|
|**通信模式**|仅支持一对一|支持一对一、一对多、多对多|

**超时重传 vs 快速重传**

|触发条件|超时重传 (Timeout)|快速重传 (Fast Retransmit)|
|:---|:---|:---|
|**现象**|计时器到期未收到 ACK|连续收到 3 个冗余 ACK|
|**拥塞判断**|认为网络严重拥塞|认为个别报文丢失，网络未严重拥塞|
|**ssthresh 调整**|设为当前 cwnd 的一半|设为当前 cwnd 的一半|
|**cwnd 调整**|重置为 1 MSS|设为新的 ssthresh 值（减半后）|
|**后续算法**|重新执行慢开始|直接执行拥塞避免（快恢复）|

## 闪卡
#card
- 传输层复用与分用的定义分别是什么？::复用指多进程共用协议发送；分用指接收方将数据交付给正确进程。
- 套接字（Socket）由哪两部分组成？::由 IP 地址和端口号拼接而成，唯一标识网络中某主机的一个应用进程。
- 熟知端口号的范围及典型应用有哪些？::范围 0~1023，如 FTP(21), SSH(22), SMTP(25), DNS(53), HTTP(80)。
- UDP 首部包含哪四个字段，总长多少？::源端口、目的端口、长度、检验和；总长固定为 8 字节。
- UDP 面向报文的特点对应用层有何要求？::应用层需选择合适报文大小，UDP 不拆分不合并，保留报文边界。
- UDP 检验和计算时为何需要伪首部？::伪首部含 IP 地址，用于验证数据报是否送达正确主机，不向下传递。
- TCP 首部中“数据偏移”字段的作用及单位？::指出首部长度，单位为 4 字节，最小值为 5（即 20 字节）。
- SYN=1 且 ACK=0 表示什么报文？::表示连接请求报文段，用于三次握手的第一步，不能携带数据。
- TCP 序号字段是对什么进行编号？::对字节流中的每个字节依次编号，而非对报文段整体编号。
- TCP 三次握手中，第二次握手报文段的标志位设置？::SYN=1, ACK=1；确认号为 x+1，自身序号为 y。
- 为何 TCP 建立连接需要三次握手而不是两次？::防止已失效的连接请求报文段突然到达服务器，导致错误建立连接浪费资源。
- SYN 报文段能否携带数据？是否消耗序号？::不能携带数据，但消耗一个序号，下次发送序号需加 1。
- TCP 释放连接时，TIME-WAIT 状态持续多久？::持续 2MSL（最长报文段寿命），确保最后 ACK 到达且旧报文消失。
- 为何 TCP 释放连接通常需要四次挥手？::因 TCP 全双工，一方发送 FIN 仅关闭发送方向，接收方向需单独发送 FIN 关闭。
- FIN 报文段是否消耗序号？::是，FIN 报文段即使不携带数据，也消耗一个序号。
- 触发 TCP 快速重传的条件是什么？::发送方连续收到 3 个对同一报文段的冗余 ACK（共 4 个确认）。
- TCP 确认序号 N 的具体含义是什么？::表示序号 N-1 及之前的所有数据已正确接收，期望收到下一个序号为 N 的数据。
- TCP 如何处理失序到达的报文段？::缓存失序报文，立即发送冗余 ACK 指明期望序号，不丢弃（不同于 GBN）。
- TCP 流量控制中，发送窗口的上限值如何计算？::取接收窗口 rwnd 和拥塞窗口 cwnd 中的较小值，即 $\min[rwnd, cwnd]$。
- 当接收方通告零窗口时，如何避免死锁？::发送方启动持续计时器，超时后发送零窗口探测报文段询问窗口状态。
- 流量控制与数据链路层流量控制的主要区别？::传输层是端到端进程间控制，窗口动态变化；链路层是相邻节点间，窗口常固定。
- TCP 慢开始阶段，拥塞窗口 cwnd 如何增长？::每经过一个传输轮次（RTT），cwnd 加倍（指数增长），直到达到 ssthresh。
- 发生超时重传时，ssthresh 和 cwnd 如何调整？::$ssthresh$ 设为当前 $cwnd$ 的一半，$cwnd$ 重置为 1，重新执行慢开始。
- 收到 3 个冗余 ACK 时，快恢复算法如何调整 cwnd？::$ssthresh$ 和 $cwnd$ 均调整为当前 $cwnd$ 的一半，直接进入拥塞避免阶段。
- MSS 设置过大或过小分别有什么负面影响？::过大导致 IP 分片增加重传开销；过小导致首部占比高，降低网络利用率。
- TCP 的重传机制更接近 GBN 还是 SR？::基础类似 GBN（累积确认），但缓存失序段并重传单个丢失段，类似 SR，支持 SACK。
- 为何超时重传 cwnd 置 1，而 3 冗余 ACK 仅减半？::超时意味着严重拥塞（ACK 未回），需剧烈减速；冗余 ACK 表明网络仍有传输能力，轻度减速。
