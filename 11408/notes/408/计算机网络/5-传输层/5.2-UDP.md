# 5.2 UDP

> [!abstract] 一句话总结
> UDP 是在 IP 数据报服务基础上仅增加复用分用与差错检测的无连接、面向报文协议，以牺牲可靠性换取低时延与灵活通信模式。

## 核心要点
### 考点1：UDP 协议特点与适用场景
**UDP 无连接、面向报文、首部开销小、支持多播且无拥塞控制，适用于实时应用或一次性少量数据传输。**
UDP 首部仅 $8\text{B}$；面向报文指保留边界不拆分合并；无拥塞控制使发送速率不受网络拥塞影响。

> [!tip] 考试怎么用
> 区分 TCP 面向字节流与 UDP 面向报文；注意 UDP 虽不可靠但应用层可自行实现可靠性。

### 考点2：UDP 首部格式与字段含义
**UDP 首部固定 8 字节，含源端口、目的端口、长度和检验和四个字段，每字段 2 字节。**
最小长度值为 $8$（仅首部）；IPv4 中检验和可置全 0 表示未使用，IPv6 强制启用。

> [!tip] 考试怎么用
> 记住首部总长 8B；目的端口必须有效，源端口无需回复时可置 0；长度字段包含首部。

### 考点3：UDP 检验和计算机制
**UDP 检验和计算需临时添加 12 字节伪首部，对首部、数据和伪首部进行二进制反码求和。**
发送方：检验和置 0，补零对齐，反码求和取反填入；接收方：反码求和，结果为全 $1$ 则无错。

> [!tip] 考试怎么用
> 伪首部不传输仅用于计算；奇数字节末尾补 0 不计入实际长度；出错通常直接丢弃。

### 考点4：二进制反码求和运算规则
**二进制反码求和需逐列相加，最高位进位需回卷加至最低位，最后取反得检验和。**
规则：$1+1=0$ 进位 1；进位回卷；发送方取反填入，接收方求和验全 1。

> [!tip] 考试怎么用
> 计算时务必处理进位回卷；接收方验证时包含检验和字段一起求和。

## 易混与对比
**UDP 面向报文 vs TCP 面向字节流**

|特性|UDP|TCP|
|---|---|---|
|数据处理单位|保留应用层报文边界，不拆分不合并|视为无结构字节流，自动拆分重组|
|长度限制|应用需选择合适大小，过长致 IP 分片|无限制，由协议自动处理|
|编号机制|无序号|每个字节有编号|

**UDP 检验和 vs IP 首部检验和**

|项目|UDP 检验和|IP 首部检验和|
|---|---|---|
|校验范围|首部 + 数据 + 伪首部|仅 IP 首部|
|伪首部|需要（含 IP 地址信息）|不需要|
|强制性|IPv6 强制，IPv4 可选|始终强制|

- **UDP 可靠性机制归属**：UDP 协议本身不提供可靠交付、流量控制和拥塞控制；若应用需要可靠性，必须由应用层自行设计实现，而非由传输层保证。

## 闪卡
#card
- UDP 为何适合视频会议等实时应用？::无拥塞控制保证稳定发送速率，容忍少量丢包但拒绝大时延。
- UDP 面向报文的具体含义是什么？::应用层交下多大报文就发送多大，不拆分不合并，保留报文边界。
- 若 UDP 报文太长交付 IP 层会导致什么后果？::导致 IP 分片，降低传输效率。
- UDP 支持哪些通信模式而 TCP 不支持？::支持一对一、一对多和多对多通信，TCP 仅支持一对一。
- DNS 和 DHCP 为何常选用 UDP？::一次性传输少量数据，避免 TCP 连接建立维护释放的显著开销。
- UDP 首部的最小长度值是多少？::8，表示仅有首部无数据部分。
- UDP 首部中哪个字段在 IPv6 中强制启用？::检验和字段。
- 若接收方发现目的端口号不正确如何处理？::丢弃报文并由 ICMP 发送“端口不可达”差错报文给发送方。
- UDP 长度字段统计的范围包括什么？::包括 UDP 首部和数据部分的总长度。
- 源端口号在什么情况下可置为全 0？::当不需要对方回复时。
- UDP 检验和计算中伪首部的作用是什么？::检测 IP 首部中源地址和目的地址是否在传输中发生改变。
- 若 UDP 数据部分长度为奇数字节如何处理？::计算时末尾临时补一个全 0 字节，不影响实际发送内容。
- 接收方验证 UDP 检验和时无差错的结果是什么？::所有 16 位字二进制反码求和结果为全 1。
- 伪首部是否会传递给网络层或应用层？::不会，仅在计算检验和时临时添加。
- UDP 检验和检出错误后通常如何处理？::直接丢弃该报文。
- 二进制反码求和中最高位产生进位如何处理？::将该进位加到结果的最低位，称为回卷。
- 发送方计算完反码求和后如何得到检验和？::对求和结果取反码。
- 接收方验证时若结果中出现 0 说明什么？::说明有差错。
- 二进制反码加法中 1+1 的结果是什么？::本位为 0 并产生进位 1。
