# 5.4 本章小结及疑难点

> [!abstract] 一句话总结
> 本节核心在于解析 TCP 如何通过 MSS 优化、混合重传策略、分级拥塞控制及三次握手机制，在不可靠的 IP 网络上实现高效且可靠的端到端交付。

## 核心要点
### 考点1：MSS 设置的影响与原则
**MSS 应尽可能大以避免首部开销过大，但必须确保在 IP 层不发生分片以防单分片丢失导致整段重传。**
默认 MSS 为 $536\text{B}$，对应 TCP 报文段总长 $536+20=556\text{B}$；有效载荷占比公式 $\eta = \frac{L_{data}}{L_{data} + 40}$。

> [!tip] 考试怎么用
> 注意 MSS 与接收窗口无关；MSS 过大导致 IP 分片，任一分片丢失需重传整个 TCP 报文段。

### 考点2：TCP 重传机制：GBN 与 SR 的混合
**TCP 基础机制类似 GBN（累积确认），但通过缓存失序报文和冗余 ACK 实现单点重传，SACK 选项使其更接近 SR。**
收到冗余 ACK 时重传丢失的第 $k$ 个报文段，后续 $k+1 \sim N$ 已缓存报文段无须重传。

> [!tip] 考试怎么用
> 区分 GBN（丢弃失序）与 TCP（缓存失序）；SACK 能明确告知发送方哪些非连续块已接收。

### 考点3：拥塞控制：超时与冗余 ACK 的区别
**超时代表严重拥塞（cwnd 置 1 进慢启动），3 个冗余 ACK 代表轻度拥塞（cwnd 减半进拥塞避免）。**
超时：$cwnd \leftarrow 1$ MSS；3 冗余 ACK：$cwnd \leftarrow cwnd / 2$（乘法减小）。

> [!tip] 考试怎么用
> 判断拥塞程度的关键：超时意味着 ACK 未返回（可能瘫痪），冗余 ACK 意味着后续包已到（网络尚通）。

### 考点4：三次握手的必要性
**三次握手能防止已失效的连接请求报文段突然到达服务器导致错误建立连接和资源浪费。**
旧 SYN 到达：三次握手中客户端不回复 ACK（序号无效）；两次握手中服务器直接建立连接等待数据。

> [!tip] 考试怎么用
> 重点掌握“失效旧 SYN

## 易混与对比
**TCP 重传机制归属**

|特性|GBN|SR|TCP 基础|TCP+SACK|
|---|---|---|---|---|
|失序处理|丢弃|缓存|缓存|缓存|
|确认方式|累积确认|单个确认|累积 + 冗余 ACK|显式非连续块|
|重传单位|从丢失处全部重传|仅重传丢失|仅重传丢失|仅重传丢失|
|结论|纯 GBN|纯 SR|GBN 与 SR 混合|更接近 SR|

- **拥塞程度判断依据**：**超时事件**：ACK 完全未返回，推测网络严重拥塞或局部瘫痪，措施最严厉（cwnd=1）。
  **3 个冗余 ACK**：后续报文段已到达接收方，推测网络仅轻微拥塞，措施较温和（cwnd 减半）。
- **可靠交付的必要性**：即使链路无差错，IP 层仍可能导致：**失序**（独立选路）、**丢失**（TTL 耗尽或拥塞丢弃）、**重复**。因此 TCP 可靠交付在无误链路下依然必需。

## 闪卡
#card
- MSS 设置过小有何后果？::网络利用率显著降低，因 40B 首部开销占比过高。
- MSS 设置过大有何风险？::触发 IP 分片，任一分片丢失会导致整个 TCP 报文段重传。
- MSS 的设定依据是什么？::避免 IP 分片，与接收方缓存大小或接收窗口无关。
- TCP 规定的默认 MSS 数值是多少？::536B（数据部分），对应总长 556B。
- TCP 收到失序报文段如何处理？::不丢弃，将其缓存并发送冗余 ACK 指明期望序号。
- 若第 k 个报文段丢失，TCP 重传范围是？::仅重传第 k 个，后续已缓存报文段不需重传。
- GBN 协议中接收方如何处理失序报文？::直接丢弃所有失序的报文段。
- SACK 选项的作用是什么？::允许接收方告知发送方哪些非连续数据块已成功接收。
- 发生超时事件时 cwnd 如何变化？::置为 1 MSS，进入慢启动阶段。
- 收到 3 个冗余 ACK 时 cwnd 如何变化？::减半（乘法减小），执行快速重传。
- 为何超时比冗余 ACK 处理更严厉？::超时表明网络可能严重拥塞或瘫痪，冗余 ACK 表明网络仍有传输能力。
- 快速重传机制触发的条件是什么？::发送方连续收到 3 个冗余 ACK。
