# 2.3 线性表的链式表示

> [!abstract] 一句话总结
> 链表以指针显式维护逻辑关系换取插入删除的高效，牺牲了随机存取能力并引入额外存储开销。

## 核心要点
### 考点1：单链表定义与头结点
**单链表通过指针建立逻辑关系，头结点使首元结点操作与其他位置统一且空表处理一致。**
typedef struct LNode{ ElemType data; struct LNode *next; } LNode, *LinkList;

> [!tip] 考试怎么用
> 判空条件：带头结点看 L->next==NULL，不带头结点看 L==NULL。

### 考点2：单链表基本操作复杂度
**单链表查找、插入、删除操作平均时间复杂度均为 O(n)，主要开销在于定位前驱结点。**
GetElem/LocateElem/ListInsert/ListDelete 时间复杂度均为 $O(n)$。

> [!tip] 考试怎么用
> 若已知结点指针，其后插入/删除复杂度为 O(1)；按序号查找必须遍历。

### 考点3：单链表插入与删除细节
**插入时先连后继再连前驱防止断链；删除给定结点可用后继数据覆盖技巧实现 O(1)。**
插入：s->next=p->next; p->next=s; 删除技巧：p->data=p->next->data; p->next=q->next; free(q);

> [!tip] 考试怎么用
> 插入步骤颠倒会导致自环；删除技巧不能用于尾结点（无后继）。

### 考点4：建立单链表方法
**头插法生成逆序链表，尾插法生成同序链表，两者总时间复杂度均为 O(n)。**
头插：s->next=L->next; L->next=s; 尾插：r->next=s; r=s; 最后 r->next=NULL;

> [!tip] 考试怎么用
> 尾插法需维护尾指针 r，头插法无需额外指针但结果逆序。

### 考点5：双链表操作特性
**双链表含 prior 和 next 指针，已知结点时插入删除可 O(1) 完成，但需维护双向链接防断链。**
插入：s->next=p->next; p->next->prior=s; s->prior=p; p->next=s; 顺序①④不可颠倒。

> [!tip] 考试怎么用
> 修改指针顺序错误会导致无法访问原后继；头结点 prior 为 NULL。

### 考点6：循环链表特性
**循环链表尾结点指向头结点形成环，可用尾指针 r 实现头尾插入均为 O(1)。**
判空：L->next==L (单) 或 L->next==L&&L->prior==L (双); 尾插：s->next=r->next; r->next=s; r=s;

> [!tip] 考试怎么用
> 循环链表无 NULL 指针；仅设尾指针 r 时，r->next 即头结点。

### 考点7：静态链表实现
**静态链表用数组模拟链式存储，next 域存下标而非指针，适用于不支持指针的语言。**
typedef struct{ ElemType data; int next; } SLinkList[MaxSize]; 结束标志 next==-1

> [!tip] 考试怎么用
> 需预分配连续空间；插入删除只改下标不移动元素；灵活性低于动态链表。

### 考点8：顺序表与链表对比
**顺序表支持随机存取 O(1) 但增删需移动元素；链表增删 O(1) 但仅支持顺序存取且密度<1。**
顺序表随机存取 $O(1)$，插入删除 $O(n)$；链表随机存取 $O(n)$，定位后增删 $O(1)$。

> [!tip] 考试怎么用
> 有序表按值查找：顺序表可折半 $O(\log n)$，链表只能顺序 $O(n)$。

## 易混与对比
**头指针 vs 头结点**

|概念|定义|存在性|作用|
|---|---|---|---|
|头指针|指向链表第一个结点的指针|任何链表必有|标识链表起始位置|
|头结点|第一个数据结点前的附加结点|仅带头结点链表有|统一操作逻辑，简化空表处理|

**插入/删除指针修改顺序**

|操作类型|错误顺序后果|正确顺序原则|
|---|---|---|
|单链表后插|先连前驱导致原后继丢失，形成自环|先连后继 (s->next)，再连前驱 (p->next)|
|双链表后插|先改 p->next 导致无法访问原后继的 prior|先连后继链 (s->next, p->next->prior)，再连前驱链|

**O(1) 删除技巧局限性**

|方法|原理|适用条件|不适用场景|
|---|---|---|---|
|常规删除|找到前驱修改指针|任意位置|需 $O(n)$ 查找前驱|
|覆盖删除|复制后继数据覆盖当前结点|已知结点指针且非尾结点|尾结点（无后继可复制）|

**循环链表判空条件**

|链表类型|普通链表判空|循环链表判空|
|---|---|---|
|单链表|L==NULL (无头) 或 L->next==NULL (有头)|L->next == L|
|双链表|同左|L->next==L 且 L->prior==L|

## 闪卡
#card
- 单链表结点包含哪两个域？::数据域 data 存放元素，指针域 next 存放后继地址。
- 引入头结点的两个主要优点？::操作统一性（首元结点无需特殊处理）和空表非空表处理统一。
- 带头结点链表的判空条件？::头指针 L 非空，但 L->next 为 NULL。
- 不带头结点链表的判空条件？::头指针 L 直接为 NULL。
- 单链表按序号查找第 i 个结点复杂度？::$O(n)$，必须从头结点开始依次遍历。
- 已知结点*p，在其后插入新结点复杂度？::$O(1)$，只需修改指针无需遍历。
- 单链表按值查找平均比较次数？::$O(n)$，需逐个比较数据域直到找到或遍历结束。
- 为何单链表插入删除主要耗时在查找？::需 $O(n)$ 时间定位前驱结点，指针修改本身仅需 $O(1)$。
- 单链表插入结点时两步操作顺序？::先 s->next=p->next，后 p->next=s，颠倒会丢失原后继。
- 如何在 O(1) 时间删除给定结点*p（非尾）？::将*p 后继数据复制到*p，然后删除其后继结点。
- 删除技巧法为何不能删除尾结点？::尾结点无后继结点，无法执行数据复制操作。
- 不带头结点链表插入首结点需特殊处理？::是，需更新头指针 L 指向新结点；带头结点则无需。
- 头插法建立链表元素顺序特点？::与输入顺序相反，新结点始终成为第一个数据结点。
- 尾插法为何需要尾指针 r？::避免每次遍历找表尾，使插入操作降为 $O(1)$。
- 两种建表法总时间复杂度？::均为 $O(n)$，每个结点插入耗时 $O(1)$。
- 尾插法最后一步关键操作？::将尾结点 r 的 next 域置为 NULL，标志链表结束。
- 双链表结点比单链表多哪个域？::prior 域，指向直接前驱结点。
- 双链表插入时哪两步顺序不可颠倒？::s->next=p->next 必须在 p->next->prior=s 之前，否则丢失后继。
- 双链表已知结点*p 删除其后继复杂度？::$O(1)$，可直接通过 prior 访问前驱无需遍历。
- 双链表头结点的 prior 域值？::NULL，表示无前驱。
- 循环单链表判空条件？::头结点的 next 指向自身，即 L->next == L。
- 为何循环链表常设尾指针 r？::r->next 即头结点，头尾插入均可 $O(1)$ 完成。
- 循环双链表空表时指针指向？::头结点 L 的 prior 和 next 均指向自身 L。
- 循环链表尾结点 next 域指向？::指向头结点，形成闭环，不为 NULL。
- 静态链表的指针域存储什么？::存储下一个结点的数组下标（游标），而非内存地址。
- 静态链表如何标志结束？::next 域值为 -1。
- 静态链表相比动态链表主要缺点？::需预分配连续空间，灵活性较差，长度受限。
- 静态链表适用场景？::不支持指针的编程语言（如 Basic）或需避免动态内存分配时。
- 哪种结构支持随机存取？::顺序表，可通过下标直接访问任意元素，复杂度 $O(1)$。
- 链表存储密度为何小于 1？::每个结点需额外存储指针域，占用非数据空间。
- 有序表按值查找效率对比？::顺序表可折半查找 $O(\log n)$，链表只能顺序查找 $O(n)$。
- 何时优先选择链式存储？::线性表长度变化大、频繁进行插入删除操作时。
