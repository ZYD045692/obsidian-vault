# 7.2 顺序查找和折半查找

> [!abstract] 一句话总结
> 顺序查找以空间换通用性，折半查找以有序换对数效率，分块查找折中二者实现索引加速。

## 核心要点
### 考点1：一般线性表的顺序查找
**顺序查找适用于顺序表和链表，不要求元素有序，通过设置哨兵可避免循环中的边界判断。**
```c\nST.elem[0] = key; // 哨兵\nfor (int i = ST.TableLen; ST.elem[i] != key; --i);\nASL_{成功} = \frac{n+1}{2}, ASL_{失败} = n+1
```

> [!tip] 考试怎么用
> 注意哨兵设在 0 号位，循环从 TableLen 开始递减；链表只能使用此方法。

### 考点2：有序线性表的顺序查找
**利用有序性，当遇到大于 key 的元素时可提前判定查找失败，降低失败时的 ASL。**
```text
判定：若 L[i].key < key 且 L[i+1].key > key，则失败。\nASL_{失败} = \frac{n}{2} + \frac{n}{n+1}
```

> [!tip] 考试怎么用
> 查找成功的 ASL 与无序表相同；此方法可用于链表，而折半查找不可。

### 考点3：折半查找算法实现
**仅适用于关键字有序的顺序表，通过不断缩小查找区间至一半来定位元素。**
```c\nwhile (low <= high) {
 mid = (low + high) / 2;
 if (L.elem[mid] == key) return mid;
 else if (L.elem[mid] > key) high = mid - 1;
 else low = mid + 1;
}
```

> [!tip] 考试怎么用
> 必须保证每次取整方式一致（均向下或均向上）；链表无法随机访问，不能用此法。

### 考点4：折半查找判定树性质
**折半查找过程对应一棵平衡二叉树，成功查找长度等于结点层数，失败查找长度等于父结点层数。**
```text
树高 h = \lceil \log_2(n+1) \rceil\nASL_{成功} \approx \log_2(n+1) - 1
时间复杂度：O(\log_2 n)
```

> [!tip] 考试怎么用
> 判定树是平衡二叉树；失败结点是方形虚结点，共 $n+1$ 个。

### 考点5：分块查找原理与 ASL
**块间有序、块内无序，先查索引表定块，再在块内顺序查找，ASL 为两者之和。**
```text\nASL = L_1 + L_S = \frac{b+1}{2} + \frac{s+1}{2}
最优块长 s = \sqrt{n}, min(ASL) = \sqrt{n} + 1
```

> [!tip] 考试怎么用
> 索引表必须有序；块内可以无序；$n=bs$，$b$为块数，$s$为块长。

## 易混与对比
**三种查找方法的适用场景对比**

|查找方法|存储结构要求|关键字有序要求|时间复杂度 (成功)|
|---|---|---|---|
|顺序查找 (一般)|顺序或链式|无要求|$O(n)$|
|顺序查找 (有序)|顺序或链式|必须有序|$O(n)$ (失败优化)|
|折半查找|仅顺序|必须有序|$O(\log_2 n)$|
|分块查找|顺序或链式|块间有序|$O(\sqrt{n})$ (最优)|

- **查找失败时的 ASL 计算差异**：一般顺序查找失败需比较 $n+1$ 次；有序顺序查找失败平均约 $n/2$ 次（提前终止）；折半查找失败取决于判定树高度，约为 $\log_2 n$。
- **判定树中成功与失败路径的定义**：折半查找和有序顺序查找均有判定树。成功长度=根到该结点路径结点数；失败长度=根到失败结点父结点的路径结点数（有序顺序查找）或失败结点本身层数（视具体定义，408 通常指父结点层数或比较次数）。

#card
- 顺序查找中引入'哨兵'的主要目的是什么？::避免在循环中反复判断数组下标是否越界，提高效率。
- 含 n 个元素的无序表，等概率下查找成功的 ASL 是多少？::$(n+1)/2$
- 顺序查找对存储结构有何要求？::无要求，顺序存储和链式存储均可使用。
- 若查找失败，一般顺序查找的关键字比较次数是多少？::$n+1$ 次
- 有序表顺序查找中，何时可提前判定查找失败？::当当前元素小于 key 且下一元素大于 key 时。
- 有序表顺序查找失败时的 ASL 近似值为多少？::约 $n/2$（公式为 $\frac{n}{2} + \frac{n}{n+1}$）
- 有序表的顺序查找能否用于链式存储？::可以，这是它与折半查找的本质区别之一。
- 有序表顺序查找的判定树中，失败结点有多少个？::$n+1$ 个
- 折半查找适用的两个必要条件是什么？::关键字有序、顺序存储结构。
- 折半查找中，若 key < mid 元素，下一步如何调整区间？::high = mid - 1，在前半部分继续查找。
- 折半查找能否用于链表？为什么？::不能，因为链表无法随机访问中间位置元素。
- 计算 mid 时向下取整和向上取整能否混用？::不能，每次查找必须采用相同的取整方式。
- 折半查找判定树中，圆形结点和方形结点分别代表什么？::圆形代表表中元素，方形代表失败区间。
- 含 n 个元素的折半查找判定树高度 h 是多少？::$h = \lceil \log_2(n+1) \rceil$
- 查找失败时的比较次数等于判定树中什么？::等于对应失败结点的父结点所在的层数。
- 折半查找判定树是否一定是平衡二叉树？::是，它满足平衡二叉树的性质。
- 分块查找中，块内元素和块间元素分别有何要求？::块内可无序，块间必须有序（前块最大 < 后块最小）。
- 分块查找的平均查找长度 ASL 由哪两部分组成？::索引查找平均长度 + 块内查找平均长度。
- 当 n 固定时，分块查找 ASL 最小的块长 s 是多少？::$s = \sqrt{n}$
- 分块查找的索引表是否必须有序？::是，索引表按各块最大关键字有序排列。
