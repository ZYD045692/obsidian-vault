# 3.2 队列

> [!abstract] 一句话总结
> 队列是仅允许一端插入另一端删除的 FIFO 线性表，核心矛盾在于顺序存储需通过循环结构或辅助标记解决假溢出问题。

## 核心要点
### 考点1：队列基本概念与操作
**队列是操作受限的线性表，遵循先进先出（FIFO）原则，仅允许在队尾插入、队头删除。**
基本操作：InitQueue(&Q), QueueEmpty(Q), EnQueue(&Q,x), DeQueue(&Q,&x), GetHead(Q,&x)。
禁止直接访问或修改中间元素。

> [!tip] 考试怎么用
> 注意区分栈（LIFO）与队列（FIFO）的操作限制，严禁越界访问中间节点。

### 考点2：顺序队列与假溢出
**顺序队列使用连续存储单元，front 指向队首，rear 指向队尾下一位置，易产生 rear 达上限但前端有空闲的假溢出。**
定义：typedef struct{ ElemType data[MaxSize]; int front, rear; } SqQueue;
初始：Q.front=Q.rear=0。
入队：data[rear]=x; rear++。
出队：x=data[front]; front++。

> [!tip] 考试怎么用
> 判空条件是 front==rear，但判满不能简单用 rear==MaxSize，需识别假溢出现象。

### 考点3：循环队列判空判满策略
**循环队列通过取模运算实现逻辑环状结构，常用牺牲一个单元、增设 size 或 tag 标志三种方法区分空满。**
指针移动：front=(front+1)%MaxSize, rear=(rear+1)%MaxSize。
长度公式：(rear-front+MaxSize)%MaxSize。
牺牲单元法判满：(rear+1)%MaxSize == front。

> [!tip] 考试怎么用
> 最常用的是牺牲一个单元法；若题目未指定，默认此法；注意长度公式中加 MaxSize 再取模。

### 考点4：循环队列代码实现
**基于牺牲一个单元法，入队前检查 (rear+1)%MaxSize==front，出队前检查 front==rear。**
入队核心：\nif((Q.rear+1)%MaxSize==Q.front) return false;\nQ.data[Q.rear]=x; Q.rear=(Q.rear+1)%MaxSize;
出队核心：\nif(Q.rear==Q.front) return false;\nx=Q.data[Q.front]; Q.front=(Q.front+1)%MaxSize;

> [!tip] 考试怎么用
> 代码中必须先判满/判空再操作指针；注意取模运算应用在指针更新处而非判断处。

### 考点5：链式队列结构与操作
**链式队列是带头结点或不带头结点的单链表，含 front 和 rear 指针，无队满限制，适合元素频繁变化场景。**
类型定义：typedef struct{ LinkNode *front, *rear; } LinkQueue;
带头结点判空：Q.front == Q.rear。
不带头结点判空：Q.front == NULL。

> [!tip] 考试怎么用
> 考试常考带头结点版本；出队时若删的是最后一个结点，需特殊处理 rear 指针指回 front。

### 考点6：双端队列及其受限形式
**双端队列允许两端插入删除；输出受限端仅能插入，输入受限端仅能删除；特定限制下可退化为栈或普通队列。**
输出受限：一端可插删，另一端仅可插。
输入受限：一端可插删，另一端仅可删。
若限定某端插入只能从该端删除，则退化为两个栈底相接的栈。

> [!tip] 考试怎么用
> 解题时可用代入验证法；注意输入受限队列一端行为像栈，另一端像普通队列出口。

## 易混与对比
**循环队列判空与判满条件的混淆**

|方法|队空条件|队满条件|特点|
|---|---|---|---|
|牺牲一个单元|$Q.front == Q.rear$|$(Q.rear+1)\%MaxSize == Q.front$|最常用，损失一个空间|
|增设 size|$Q.size == 0$|$Q.size == MaxSize$|空间利用率 100%，需额外变量|
|增设 tag|$front==rear$ 且 $tag=0$|$front==rear$ 且 $tag=1$|空间利用率 100%，需额外变量|

**带头结点与不带头结点链队列的判空差异**

|类型|队空条件|删除最后一个元素后的操作|
|---|---|---|
|带头结点|$Q.front == Q.rear$|$Q.rear$ 指向头结点 ($Q.front$)|
|不带头结点|$Q.front == NULL$|$Q.front$ 和 $Q.rear$ 均置为 NULL|

- **输入受限与输出受限双端队列的能力差异**：对于序列 1,2,3,4：
  - 输入受限不能得到：4,2,3,1 和 4,2,1,3（注：原文例题结论为 4,2,3,1 和 4,2,1,3 中的一部分，具体依操作序列而定，原文结论是：输入受限得不到 4,2,3,1 和 4,2,1,3 中的 4,2,1,3 是输出受限能得到而输入受限不能得到的；4,2,3,1 是两者都不能得到的）。
  - 修正原文结论记忆：
  1. 输入受限能得到但输出受限不能：4,1,3,2
  2. 输出受限能得到但输入受限不能：4,2,1,3
  3. 两者都不能得到：4,2,3,1

## 闪卡
#card
- 队列的插入和删除分别在哪一端进行？::插入在队尾（Rear），删除在队头（Front）。
- 队列的逻辑特性是什么？::先进先出（First In First Out, FIFO）。
- 能否直接访问队列中间的元素？::不能，队列是操作受限的线性表，仅能操作两端。
- GetHead 操作会改变队列状态吗？::不会，它只读取队首元素值，不执行出队删除。
- 顺序队列中 front 和 rear 的初始值通常设为多少？::通常均初始化为 0。
- 顺序队列中 rear 指针通常指向什么位置？::指向队尾元素的下一个位置（待插入位置）。
- 什么是顺序队列的“假溢出”？::rear 已达数组上限，但 front 前方仍有空闲单元，导致无法入队。
- 仅凭 rear==MaxSize 能判断顺序队列已满吗？::不能，这可能只是假溢出，数组前端可能仍有空间。
- 循环队列中指针加 1 的操作如何实现？::使用取模运算：(pointer + 1) % MaxSize。
- 牺牲一个单元法中，队满的条件是什么？::(Q.rear + 1) % MaxSize == Q.front。
- 增设 size 成员时，如何区分队空和队满？::队空 size==0，队满 size==MaxSize，此时 front 仍等于 rear。
- 增设 tag 标志位时，tag=1 且 front==rear 表示什么？::表示队满（最近一次操作是入队）。
- 循环队列元素个数计算公式是什么？::(Q.rear - Q.front + MaxSize) % MaxSize。
- 循环队列入队操作中，何时返回 false？::当 (Q.rear + 1) % MaxSize == Q.front 时，表示队满。
- 循环队列出队操作中，何时返回 false？::当 Q.rear == Q.front 时，表示队空。
- 入队成功后，rear 指针如何更新？::Q.rear = (Q.rear + 1) % MaxSize。
- 出队成功后，front 指针如何更新？::Q.front = (Q.front + 1) % MaxSize。
- 带头结点的链式队列，队空条件是什么？::Q.front == Q.rear。
- 不带头结点的链式队列，队空条件是什么？::Q.front == NULL (且 Q.rear == NULL)。
- 链式队列是否存在“队满”情况？::不存在，只要内存足够即可动态分配结点。
- 链式队列出队时，若删除的是最后一个结点，需做什么？::需将 Q.rear 重新指向 Q.front（头结点），防止悬空。
- 何种场景优先选用链式队列？::元素数量频繁变化或多队列共存避免存储分配不合理时。
- 输出受限的双端队列，受限端允许什么操作？::仅允许插入，不允许删除。
- 输入受限的双端队列，受限端允许什么操作？::仅允许删除，不允许插入。
- 若双端队列某端插入的元素只能从该端删除，它退化成什么？::退化为两个栈底相邻接的栈。
- 双端队列两端地位是否平等？::是，两端均可进行插入和删除操作（除非受限）。
