# 5.4 本章疑难点

> [!abstract] 一句话总结
> 设备分配通过逻辑名映射与多通路重试机制突破物理瓶颈，I/O 缓冲则利用用户/内核双层缓存策略分别优化系统调用开销与磁盘访问效率。

## 核心要点
### 考点1：增强设备无关性的分配策略
**进程使用逻辑设备名发起请求，系统遍历同类设备 DCT 直至找到可用者，仅当全忙时才挂起进程。**
分配流程：查找 SDT $\to$ 遍历 DCT 链表 $\to$ 若忙则试下一个 $\to$ 全忙则挂起加入等待队列。

> [!tip] 考试怎么用
> 易错点：并非请求即挂起，必须遍历完该类所有设备确认均忙后才挂起。

### 考点2：多通路 I/O 结构的分配机制
**为避免瓶颈，控制器与通道分配需逐级尝试，仅当所有相关路径均不可用时分配才失败。**
重试逻辑：若首控制器/通道忙 $\to$ 试下一个 $\to$ 全不可用则挂起；有一可用即成功。

> [!tip] 考试怎么用
> 考点：多通路设计不仅针对设备，也包含控制器和通道的冗余尝试。

### 考点3：设备分配的“三关”检查
**成功分配设备须依次通过 SDT、DCT、COCT、CHCT 检查，确保设备、控制器、通道三者同时可用。**
访问顺序：SDT $\to$ DCT $\to$ COCT $\to$ CHCT；条件：设备可用 $\land$ 控制器可用 $\land$ 通道可用。

> [!tip] 考试怎么用
> 常考选择题：设备分配需要访问哪四张表？缺一不可的条件是什么？

### 考点4：用户缓冲区的定义与作用
**用户缓冲区是进程预申请的内存区域，用于暂存 read 读取的数据，主要作用是减少系统调用次数。**
工作流程：申请 Buffer $\to$ 调用 read 填充 $\to$ 应用处理 $\to$ 再次 read；目的：降低用户态/内核态切换开销。

> [!tip] 考试怎么用
> 区分点：用户缓冲区优化的是“系统调用频率”，而非直接优化磁盘 I/O 效率。

### 考点5：内核缓冲区的定义与作用
**内核缓冲区由 OS 维护，用于缓存磁盘数据或暂存写数据，核心目的是提升磁盘 I/O 整体效率。**
读操作：查内核缓冲 $\to$ 有则复制给用户，无则挂起进程读盘 $\to$ 读入后复制并唤醒；写操作：先写内核缓冲，满足条件批量写盘。

> [!tip] 考试怎么用
> 易错点：写操作通常不立即写盘，而是积累到一定量或满足特定条件才刷新。

## 易混与对比
**用户缓冲区 vs 内核缓冲区**

|特性|用户缓冲区|内核缓冲区|
|---|---|---|
|**位置**|用户进程空间（如数组）|操作系统内核空间|
|**主要目的**|减少系统调用次数，降低态切换开销|提升磁盘 I/O 整体效率，优化写操作|
|**读操作流程**|接收从内核复制来的数据供应用处理|先查缓存，无则发起磁盘 I/O 并挂起进程|
|**写操作流程**|提交数据给内核|暂存数据，批量或条件满足时写入磁盘|

**设备分配失败 vs 进程挂起时机**

|场景|改进前/简单策略|改进后策略（本章重点）|
|---|---|---|
|**设备忙**|可能直接失败或挂起|继续查找同类下一个 DCT|
|**控制器/通道忙**|可能直接失败|尝试下一个控制器或通道|
|**挂起条件**|单个资源忙|所有同类设备（或所有通路）均不可用|

## 闪卡
#card
- 进程发起 I/O 请求时使用什么名称？::逻辑设备名，而非物理设备名。
- 若第一个 DCT 对应设备正忙，系统立即挂起进程吗？::否，继续查找该类设备的下一个 DCT。
- 进程被挂起并加入等待队列的触发条件是什么？::该类所有同类设备均处于忙碌状态。
- 只要存在一个可用设备，系统后续做什么？::进入安全性检查与分配流程。
- 多通路 I/O 结构中，若第一个控制器正忙如何处理？::尝试下一个控制器，而非直接失败。
- 通道分配失败的判定条件是什么？::所有相关通道均不可用。
- 多通路设计的主要目的是什么？::避免 I/O 瓶颈，提高分配成功率。
- 只要有一个控制器或通道可用，分配结果如何？::即可完成分配。
- 具有通道的系统中，设备分配依次访问哪四张表？::SDT $\to$ DCT $\to$ COCT $\to$ CHCT。
- 成功分配一个设备必须同时满足哪三个条件？::设备可用、控制器可用、通道可用。
- 为何称设备分配要过“三关”？::因需同时确认设备、控制器、通道三者皆可用。
- 若设备可用但控制器忙，分配能成功吗？::不能，必须三者同时可用。
- 用户缓冲区通常由谁预先申请？::用户进程（如定义一个数组）。
- 用户缓冲区的主要作用是什么？::减少系统调用次数，降低态切换开销。
- 何时发起下一次 read 系统调用？::当缓冲区中数据被处理完毕后。
- 操作系统将读取数据填充到哪里？::用户进程的缓冲区中。
- 内核缓冲区位于哪里？::操作系统内核空间。
- 读操作时若内核缓冲无所需数据，进程状态如何？::进程被挂起，转而调度其他进程。
- 写操作中，数据何时写入磁盘？::当数据积累到一定量或满足特定刷新条件时。
- 内核缓冲区的核心目的是什么？::提升磁盘 I/O 的整体效率。
- 哪种操作在内核缓冲中优化效果最突出？::写操作。
