# 5.2 设备独立性软件

> [!abstract] 一句话总结
> 设备独立性软件通过统一接口、缓冲管理及逻辑映射屏蔽硬件差异，利用 SPOOLing 等技术将独占设备虚拟化为共享设备以解决速度匹配与资源竞争问题。

## 核心要点
### 考点1：设备独立性软件功能
**该层位于驱动程序之上，核心职责是实现各类设备的公共操作，为上层提供统一抽象的 I/O 接口。**
五大功能：1.统一驱动接口（抽象名映射物理名）；2.缓冲管理；3.差错控制（暂时性重试/持久性记坏块）；4.独占设备分配回收；5.提供统一逻辑数据块。

> [!tip] 考试怎么用
> 区分暂时性错误（驱动处理，重试）与持久性错误（OS 处理，记坏块表）；注意逻辑块大小屏蔽了字符/块设备差异。

### 考点2：单缓冲时间计算
**单缓冲中设备写入与 CPU 处理可并行，但缓冲区访问需互斥，导致串行段 M 无法重叠。**
设填入时间$T$，传送时间$M$，处理时间$C$。每块数据耗时：$\max(T, C) + M$。

> [!tip] 考试怎么用
> 易错点：误以为$T$和$C$完全并行忽略了$M$的串行特性；当$T>C$时瓶颈在设备，反之在 CPU。

### 考点3：双缓冲时间计算
**双缓冲允许设备向一空缓冲区写入的同时，系统从另一满缓冲区取数并处理，进一步重叠操作。**
设填入时间$T$，传送 + 处理时间$C+M$。每块数据耗时：$\max(T, C + M)$。

> [!tip] 考试怎么用
> 关键区别：双缓冲中$M$可与$T$并行（在不同缓冲区），故公式中$M$并入$C$侧比较。

### 考点4：循环缓冲与缓冲池
**循环缓冲通过多缓冲区队列解决速率差异大时的同步问题；缓冲池则是统一管理多个缓冲区的软件机制。**
循环缓冲同步：1.in 追上 out（受计算限制，输入阻塞）；2.out 追上 in（受 I/O 限制，计算阻塞）。缓冲池队列：空缓冲队列、输入队列、输出队列。

> [!tip] 考试怎么用
> 循环缓冲不涉及定量时间计算；缓冲池缓冲区有四种角色（收容/提取 输入/输出）。

### 考点5：高速缓存与缓冲区对比
**高速缓存保存慢速设备数据副本以提高重复访问效率；缓冲区暂存传输中数据以协调速度差异。**
区别核心：Cache 存副本（可长期驻留，目的是减少低速设备访问）；Buffer 存传输流（传完即释，目的是匹配速度与并行）。

> [!tip] 考试怎么用
> 不要混淆目的：Cache 是为了“快”（命中则不访盘），Buffer 是为了“通”（缓解速度不匹配）。

### 考点6：设备分配数据结构与步骤
**设备分配需依次检查设备、控制器、通道状态，任一忙则进程阻塞，利用 DCT/COCT/CHCT 管理从属关系。**
分配顺序：1.查 SDT 找 DCT（设备忙则挂设备队列）；2.查 COCT（控制器忙则挂控制器队列）；3.查 CHCT（通道忙则挂通道队列）。

> [!tip] 考试怎么用
> 必须三者全空闲才算分配成功；逻辑设备名通过 LUT 映射到物理设备名以实现独立性。

### 考点7：设备分配安全性策略
**安全分配方式进程请求 I/O 后即阻塞，避免死锁但效率低；不安全方式允许进程继续运行，效率高但可能死锁。**
安全方式：请求 I/O->阻塞->完成唤醒（无其他资源请求，无死锁）。不安全方式：请求 I/O->继续运行->需资源且被占才阻塞（可能循环等待）。

> [!tip] 考试怎么用
> 安全方式牺牲了 CPU 与 I/O 的并行性；不安全方式需配合死锁避免算法（如银行家算法）。

### 考点8：SPOOLing 技术原理
**SPOOLing 利用磁盘作为巨大缓冲区，通过输入/输出进程模拟脱机操作，将独占设备虚拟为共享设备。**
组成：输入/输出井（磁盘）、输入/输出缓冲区（内存）、输入/输出进程。流程：用户->输出井（快）->后台进程->物理设备（慢）。

> [!tip] 考试怎么用
> 本质是“以空间换时间”和“虚拟化”；用户感觉独占，实际是排队写磁盘，由后台串行打印。

### 考点9：设备驱动程序功能
**驱动程序接收抽象 I/O 请求，转换为具体设备命令，检查状态，启动设备并响应中断。**
核心功能：1.抽象转具体（如逻辑块号转磁道扇区）；2.合法性检查；3.发出 I/O 命令（忙则挂队列）；4.响应中断。

> [!tip] 考试怎么用
> 驱动需可重入以支持并发；直接操作硬件，与 I/O 控制方式（中断/DMA）紧密相关。

### 考点10：I/O 操作流程实例
**I/O 操作涉及用户态与内核态切换，数据先从设备到内核缓冲区，再复制到用户缓冲区。**
流程：scanf 触发 read 系统调用->陷入内核->驱动将数据从端口送入内核缓冲区->中断唤醒->复制内核缓冲到用户缓冲->返回用户态。

> [!tip] 考试怎么用
> 两次复制：设备->内核缓冲（驱动做），内核缓冲->用户缓冲（设备无关软件做）。

## 易混与对比
**单缓冲 vs 双缓冲时间公式**

|特性|单缓冲|双缓冲|
|---|---|---|
|并行对象|设备填缓冲 vs CPU 处理前一块|设备填缓冲 vs (传送 + 处理)|
|串行部分|$M$ (传送) 必须串行|无明显串行瓶颈，取决于$max$|
|公式|$\max(T, C) + M$|$\max(T, C + M)$|
|关键点|$M$ 总是额外增加|$M$ 被合并到 $C$ 侧参与比较|

**高速缓存 (Cache) vs 缓冲区 (Buffer)**

|维度|高速缓存 (Cache)|缓冲区 (Buffer)|
|---|---|---|
|数据性质|慢速设备数据的副本|正在传输中的流动数据|
|驻留时间|可长期驻留，直到被替换|传输完成后立即释放|
|核心目的|提高重复访问效率 (减少 IO)|协调速度差异，提高并行性|
|典型场景|磁盘高速缓存|键盘输入缓冲、打印缓冲|

**安全分配 vs 不安全分配**

|特性|安全分配方式|不安全分配方式|
|---|---|---|
|进程行为|请求 I/O 后立即阻塞|请求 I/O 后继续运行|
|资源请求|阻塞期间不请求其他资源|可继续请求其他资源|
|死锁风险|无死锁 (破坏循环等待)|可能死锁 (存在循环等待)|
|系统效率|低 (CPU 与 I/O 串行)|高 (CPU 与 I/O 并行)|

**独占设备 vs 虚拟设备 (SPOOLing)**

|特性|独占设备 (物理)|虚拟设备 (SPOOLing)|
|---|---|---|
|分配方式|进程独占直到释放|多个进程并发提交，后台串行|
|用户感知|独占，其他进程需等待|感觉独占，实际写入磁盘即返回|
|实现机制|直接控制硬件|利用磁盘井 + 输入输出进程模拟|
|典型代表|打印机 (无 SPOOLing)|假脱机打印机系统|

## 闪卡
#card
- 设备独立性软件位于哪两层之间？::位于设备驱动程序之上，是内核 I/O 子系统的最高层。
- 持久性错误（如磁盘划痕）如何处理？::操作系统将其记录至坏块表，后续 I/O 自动绕过，避免更换整盘。
- 为何要提供统一的逻辑数据块？::屏蔽字符设备（字节）与块设备（固定块长）的差异，使上层无须感知底层特性。
- 独占设备释放时若等待队列为空怎么做？::置设备状态为“空闲”，完成回收；若非空则唤醒队首进程。
- 单缓冲处理一块数据的总时间公式？::$\max(T, C) + M$，其中$M$为缓冲区到工作区的传送时间。
- 当$T > C$时，单缓冲的瓶颈是什么？::设备输入速度慢，CPU 需等待设备填满缓冲区，耗时取决于$T$。
- 单缓冲中设备与 CPU 能否同时访问缓冲区？::不能，单缓冲区是共享资源，访问必须互斥，否则数据会冲突。
- 若$T < C$，处理一块数据需多久？::$C + M$，因为设备快，CPU 处理完前设备已停，总耗时由 CPU 决定。
- 双缓冲处理一块数据的总时间公式？::$\max(T, C + M)$，其中$T$为输入时间，$C+M$为处理与传送总时间。
- 当$T > C + M$时，双缓冲的耗时由谁决定？::由设备输入时间$T$决定，因为设备慢，CPU 处理完需等待设备填满。
- 双缓冲如何实现全双工通信？::每台机器需分别设置发送缓冲区和接收缓冲区，共两个缓冲区才能同时收发。
- 双缓冲中$T$与$C+M$的关系？::两者可并行执行，系统总耗时取两者的最大值。
- 循环缓冲中'in 追上 out'意味着什么？::输入快于计算，所有缓冲区已满，输入进程阻塞，系统受计算限制。
- 循环缓冲中'out 追上 in'意味着什么？::计算快于输入，所有缓冲区为空，计算进程阻塞，系统受 I/O 限制。
- 缓冲池中包含哪三种队列？::空缓冲队列、输入队列（装满输入数据）、输出队列（装满输出数据）。
- 缓冲池中'收容输入'的操作流程？::从空队列摘取空缓冲区->写入数据->装满后挂到输入队列队尾。
- 高速缓存中存放的是什么数据？::已存在于慢速设备上的数据副本，可长期驻留直至被替换。
- 缓冲区中存放的是什么数据？::正在传输过程中的数据，源自发送方，传输完成后通常立即释放。
- 高速缓存的主要目的是什么？::提高重复访问效率，若数据在缓存中则避免访问低速设备。
- 缓冲区的主要目的是什么？::协调速度差异、降低中断频率、匹配数据粒度，提高并行性。
- 设备分配的正确检查顺序是什么？::先分配设备（查 DCT），再分配控制器（查 COCT），最后分配通道（查 CHCT）。
- 若设备空闲但控制器忙，进程如何处理？::进程 PCB 被挂入控制器等待队列，直到控制器空闲。
- 系统设备表（SDT）的作用是什么？::整个系统只有一张，作为所有物理设备的全局索引，包含类型和标识符。
- 逻辑设备表（LUT）包含哪些内容？::逻辑设备名、物理设备名、驱动程序入口地址，用于实现设备独立性映射。
- 安全分配方式如何避免死锁？::进程发出 I/O 请求后立即阻塞，不再请求其他资源，破坏了循环等待条件。
- 安全分配方式的主要缺点是什么？::CPU 与 I/O 设备串行工作，系统效率较低。
- 不安全分配方式何时会导致进程阻塞？::仅当所请求的设备已被其他进程占用时，进程才进入阻塞态。
- 不安全分配方式的主要风险是什么？::进程可同时持有多个设备，可能因循环等待而造成死锁。
- SPOOLing 技术将什么设备改造为共享设备？::将物理独占设备（如打印机）改造为逻辑上的共享设备。
- SPOOLing 系统中的'井'位于哪里？::位于磁盘上，分为输入井和输出井，用于暂存大量数据。
- SPOOLing 如何实现虚拟设备功能？::为每个进程在输出井分配独立区域，使各进程认为自己独占一台设备。
- SPOOLing 中真正执行打印的是谁？::后台的假脱机打印进程，它检查队列并按序将数据从输出井送至物理打印机。
- 设备驱动程序如何处理忙设备？::若设备正忙，将请求进程的 PCB 挂到该设备的等待队列上以待调度。
- 驱动程序为何要设计为可重入的？::为了支持多个进程对同一设备的并发调用，防止数据冲突。
- 驱动程序将逻辑盘块号转换为什么？::转换为磁盘的盘面号、磁道号和扇区号等具体物理地址。
- 设备驱动程序与什么紧密相关？::与设备所采用的 I/O 控制方式（如中断驱动、DMA 方式）紧密相关。
- 键盘输入字符首先存入哪里？::首先由驱动程序送入内核缓冲区，而非直接存入用户变量。
- 谁负责将数据从内核缓冲区复制到用户缓冲区？::设备无关的 I/O 软件层（系统调用服务例程），因其不依赖具体硬件。
- 系统调用 read 执行前 CPU 处于什么状态？::用户态，执行 trap 指令后陷入内核态执行服务例程。
- 中断处理程序执行完后进程状态如何变化？::进程 P 被唤醒并加入就绪队列，等待调度再次获得 CPU。
