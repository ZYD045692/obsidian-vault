# 5.1 I_O 管理概述

> [!abstract] 一句话总结
> I/O 管理的核心矛盾是高速 CPU 与低速外设的速度差异，其演进本质是通过软硬件协作不断减少 CPU 对数据传输的干预。

## 核心要点
### 考点1：I/O 设备分类与特性
**I/O 设备按共享属性分为独占、共享和虚拟设备，其中虚拟设备通过 SPOOLing 技术将独占设备改造为逻辑共享设备。**
虚拟设备实质：利用高速共享设备（如磁盘）作为缓冲区，实现独占设备的逻辑共享。

> [!tip] 考试怎么用
> 重点区分共享设备（物理上可分时，如磁盘）与虚拟设备（逻辑上改造，如 SPOOLing 后的打印机）。

### 考点2：I/O 端口编址方式
**I/O 端口编址分为独立编址和统一编址，前者需专用指令但译码简单，后者编程灵活但占用内存空间。**
独立编址：CPU 通过专用 I/O 指令（如 IN/OUT）访问，地址空间独立。
统一编址：I/O 端口占用主存地址空间，使用普通访存指令访问。

> [!tip] 考试怎么用
> 易错点：统一编址会减少系统可用内存容量，且译码电路通常更复杂。

### 考点3：程序直接控制方式
**程序直接控制方式采用轮询机制，CPU 与 I/O 设备串行工作，导致 CPU 利用率极低。**
工作流程：CPU 发指令 -> 循环测试状态寄存器 -> 数据就绪则传输 -> 重复。
缺点：CPU 绝大部分时间处于等待测试中，无法并行。

> [!tip] 考试怎么用
> 识别关键词“轮询”、“串行”、“利用率低”，此方式未采用中断机制。

### 考点4：中断驱动方式
**中断驱动方式允许设备主动通知 CPU，实现了 CPU 与设备的并行工作，但数据交换仍以字/字节为单位经 CPU 寄存器。**
流程：CPU 发命令 -> 继续执行其他任务 -> 设备完成发中断 -> CPU 保存现场 -> 执行中断处理程序传输数据。
局限：每次仅传一个字/字节，频繁中断开销大。

> [!tip] 考试怎么用
> 注意中断发生时进程状态变化：运行态->阻塞态（原进程），运行态->内核态（中断处理）。

### 考点5：DMA 控制方式
**DMA 方式在设备与内存间建立直接数据通路，以数据块为单位传输，仅在开始和结束时需 CPU 干预。**
DMA 寄存器：MAR(内存地址), DC(数据计数), CR(命令/状态), DR(数据缓冲)。
流程：CPU 初始化 DMA -> DMA 接管总线突发传输 -> 结束发中断。

> [!tip] 考试怎么用
> 核心考点：DMA 传输过程不经过 CPU 寄存器；CPU 仅在始末介入。

### 考点6：通道控制方式
**通道是一种专用处理机，能执行通道程序自主管理多台设备的复杂 I/O 任务，进一步减少 CPU 干预。**
通道 vs DMA：通道可执行程序动态确定参数，管理多台设备；DMA 需 CPU 预设参数，通常服务单台设备。
通道程序存放于主存。

> [!tip] 考试怎么用
> 通道具备指令集但功能单一，无独立主存，受 CPU 控制。

### 考点7：I/O 软件层次结构
**I/O 软件分为用户层、设备独立性层、设备驱动层和中断处理层，其中设备独立性层负责逻辑名到物理名的映射。**
层次功能：
1. 用户层：库函数。
2. 设备独立性：公共操作、映射、缓冲。
3. 驱动层：转换抽象请求为具体指令。
4. 中断层：响应硬件中断。

> [!tip] 考试怎么用
> 常考各层功能归属，特别是“逻辑设备名映射”和“统一接口”属于设备独立性层。

### 考点8：阻塞与非阻塞 I/O
**阻塞 I/O 在数据未就绪时挂起进程，非阻塞 I/O 立即返回状态，前者实现简单后者适合高并发但需轮询。**
阻塞 I/O：进程移入等待队列，无法执行其他任务。
非阻塞 I/O：立即返回错误状态（如 -1），进程可继续执行。

> [!tip] 考试怎么用
> 非阻塞 I/O 若频繁检查状态，本质上仍是轮询，可能浪费 CPU。

## 易混与对比
**四种 I/O 控制方式对比**

|方式|数据传送单位|CPU 干预频率|数据通路|并行程度|
|---|---|---|---|---|
|程序直接控制|字/字节|极高（每条指令）|设备->CPU->内存|串行|
|中断驱动|字/字节|高（每个字/字节）|设备->CPU->内存|部分并行|
|DMA|数据块|低（每块始末）|设备<->内存|高度并行|
|通道|记录/块组|极低（每组任务）|设备<->内存|最高并行|

**独立编址 vs 统一编址**

|特性|独立编址 (I/O 映射)|统一编址 (内存映射)|
|---|---|---|
|地址空间|独立于主存|占用主存地址空间|
|访问指令|专用 I/O 指令 (IN/OUT)|普通访存指令 (LOAD/STORE)|
|硬件成本|控制信号复杂，译码简单|控制信号简单，译码复杂|
|主要缺点|指令功能有限，灵活性差|减少可用内存容量|

- **共享设备 vs 虚拟设备**：**共享设备**：物理上允许多个进程分时交替访问（如磁盘），是硬件固有属性。
  **虚拟设备**：通过 SPOOLing 技术将**独占设备**（如打印机）改造为逻辑上的共享设备，利用磁盘作为缓冲区模拟多台风设备，是软件模拟结果。
- **设备独立性层 vs 设备驱动层**：**设备独立性层**：执行所有设备的**公共操作**（分配、回收、逻辑名映射、缓冲），提供**统一接口**，屏蔽设备差异。
  **设备驱动层**：执行**特定设备**的操作，将抽象命令转换为**具体硬件指令**，直接控制设备控制器。

## 闪卡
#card
- 块设备与字符设备在寻址特性上有何根本区别？::块设备支持随机访问（可寻址），字符设备不可寻址只能顺序存取。
- 典型的独占设备有哪些？其分配原则是什么？::典型如打印机；任一时刻仅允许一个进程独占，直至使用完毕释放。
- 虚拟设备是如何实现独占设备共享的？::通过 SPOOLing 技术，利用高速共享设备（磁盘）作为缓冲区模拟多个逻辑设备。
- 磁盘属于哪类共享属性设备？为什么？::共享设备；允许多个进程逻辑上并发访问，物理上分时交替使用。
- 独立编址方式下，CPU 如何区分访问的是内存还是 I/O 端口？::通过专用的 I/O 指令（如 IN/OUT）与控制信号，地址空间逻辑分离。
- 统一编址方式的主要缺点是什么？::I/O 端口占用主存地址空间，减少了系统可用内存容量。
- 哪种编址方式无需专用 I/O 指令且编程更灵活？::统一编址（内存映射方式），使用普通加载存储指令即可访问。
- 独立编址方式在硬件设计上的优点是什么？::所需地址线较少，译码电路简单，寻址速度快。
- 程序直接控制方式中，CPU 如何知道 I/O 操作已完成？::CPU 不断地循环测试设备状态寄存器（轮询），直到标志位变化。
- 程序直接控制方式下，CPU 与 I/O 设备的工作关系是？::串行工作；CPU 必须等待设备，无法同时执行其他任务。
- 为何程序直接控制方式的 CPU 利用率相当低？::CPU 速度远快于 I/O 设备，大部分时间浪费在循环测试状态上。
- 中断驱动方式相比程序轮询，提升了什么性能？::CPU 利用率；设备准备数据期间 CPU 可并行执行其他任务。
- 中断驱动方式中，数据从设备到内存经过哪里？::必须经过 CPU 中的寄存器（设备->CPU 寄存器->内存）。
- 中断驱动方式为何不适合高速块设备的大规模数据传输？::CPU 以字/字节为单位干预，频繁中断导致处理开销过大，效率低。
- 中断处理程序执行时，原 I/O 请求进程处于什么状态？::阻塞态；直到中断处理完成并唤醒该进程。
- DMA 方式中，数据传输的基本单位是什么？::数据块；不再是以字或字节为单位。
- DMA 传输过程中，数据是否经过 CPU 寄存器？::不经过；数据直接在 I/O 设备与内存之间传输。
- CPU 在 DMA 方式中介入的时机是何时？::仅在数据块传送的开始（初始化）和结束（处理中断）时。
- DMA 控制器中哪个寄存器记录需传送的字/节总数？::数据计数器（DC）。
- 通道与通用处理机的主要区别是什么？::通道指令集专用于 I/O 控制，功能单一，且无独立主存。
- 通道与 DMA 在管理设备数量上有何不同？::一个通道可同时管理多台设备；每个 DMA 控制器通常仅服务一台设备。
- 通道程序的存放位置在哪里？::存放在主机内存中，由通道读取执行。
- 通道方式如何进一步减少 CPU 干预？::CPU 仅发一条指令，通道自主执行程序完成全部复杂 I/O 操作。
- 哪一层软件负责将逻辑设备名映射为物理设备名？::设备独立性软件层。
- 设备驱动程序的主要任务是什么？::将上层抽象 I/O 请求转换为设备控制器能识别的具体指令。
- I/O 软件层次中，哪一层直接与硬件寄存器交互？::设备驱动程序（通过控制器）和中断处理程序。
- 设备独立性层提供的统一接口有何作用？::使应用程序无须关心具体物理设备，提高可移植性和灵活性。
- 阻塞 I/O 模式下，当数据未就绪时进程状态如何变化？::进程立即被阻塞，移入等待队列，无法执行其他任务。
- 非阻塞 I/O 调用在数据未就绪时返回什么？::立即返回一个表示“暂无数据”的错误状态（如 -1）。
- 非阻塞 I/O 的主要缺点是什么？::若采用轮询频繁检查状态，会浪费 CPU 资源。
- 哪种 I/O 模式编程模型简单且是多数操作系统默认模式？::阻塞 I/O。
