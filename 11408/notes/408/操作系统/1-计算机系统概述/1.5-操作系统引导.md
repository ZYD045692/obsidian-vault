# 1.5 操作系统引导

> [!abstract] 一句话总结
> 操作系统引导是 BIOS 通过链式加载 MBR、PBR 及启动管理器，最终将内核载入内存并移交控制权的硬件初始化过程。

## 核心要点
### 考点1：CPU 激活与 BIOS 初始化
**计算机通电后 CPU 直接从 ROM 读取并执行 BIOS 程序以初始化基本硬件。**
执行流程：$\text{Power On} \to \text{CPU Fetch ROM} \to \text{Exec BIOS} \to \text{Init HW} \to \text{Build Interrupt Vector Table}$

> [!tip] 考试怎么用
> 注意 BIOS 存储在 ROM 中，且中断向量表是在此阶段建立的，而非内核加载后。

### 考点2：硬件自检与启动设备选择
**BIOS 执行 POST 自检通过后，依据 CMOS 设置确定的优先级选择首个有效启动设备。**
选择逻辑：$\text{POST Pass} \xrightarrow{\text{Read CMOS}} \text{Sort Devices} \to \text{Select First Valid Device}$

> [!tip] 考试怎么用
> 启动顺序保存在由电池供电的 CMOS 中，而非 ROM 或硬盘；POST 失败则无法进入后续引导。

### 考点3：加载主引导记录 (MBR)
**BIOS 将所选启动设备的首扇区（MBR）加载到内存，MBR 包含引导代码和硬盘分区表。**
MBR 结构：$\text{MBR} = \{ \text{Boot Code}, \text{Partition Table} \}$，位置：设备首扇区

> [!tip] 考试怎么用
> MBR 位于启动设备的第一个扇区，不是活动分区的第一个扇区；它不负责加载内核，只负责找活动分区。

### 考点4：定位活动分区与加载 PBR
**MBR 引导代码解析分区表，识别“活动”分区并加载其首扇区（PBR）到内存。**
跳转逻辑：$\text{MBR Code} \xrightarrow{\text{Parse Table}} \text{Find Active Partition} \to \text{Load PBR (1st Sector)}$

> [!tip] 考试怎么用
> 只有标记为“活动”的分区才会被加载 PBR；PBR 是分区的首扇区，不是整个硬盘的首扇区。

### 考点5：加载启动管理器
**PBR 代码负责加载启动管理器（如 GRUB/Bootmgr），由其提供多系统选择界面。**
典型代表：Linux (GRUB), Windows (Bootmgr)；功能：$\text{User Select} \to \text{Load Kernel Image}$

> [!tip] 考试怎么用
> 启动管理器是用户干预引导过程的最后一个环节，负责加载具体的内核映像。

### 考点6：加载内核与接管控制权
**启动管理器将内核映像加载到内存并跳转执行，内核接管控制权后不再依赖 BIOS 服务。**
关键动作：$\text{Load Kernel} \to \text{Jump Entry} \to \text{Rebuild Interrupts} \to \text{No BIOS Dependency}$

> [!tip] 考试怎么用
> 内核一旦运行，必须重建中断处理机制，此后硬件访问不再通过 BIOS 中断调用。

### 考点7：内核初始化与用户环境启动
**内核初始化内存、进程调度及设备驱动模块，并启动首个用户态进程（如 init）构建用户环境。**
初始化序列：1.内存 (页表/地址空间) 2.进程 (PCB/队列) 3.设备 (DCB/缓冲区) $\to \text{Start init}$

> [!tip] 考试怎么用
> 首个用户态进程是用户环境的起点；PCB 链表和就绪/阻塞队列在此阶段初始化。

## 易混与对比
**MBR 与 PBR 的区别**

|特征|MBR (主引导记录)|PBR (分区引导记录)|
|---|---|---|
|位置|启动设备的首扇区|活动分区的首扇区|
|内容|引导代码 + 硬盘分区表|加载启动管理器的代码|
|执行者|BIOS 加载并执行|MBR 引导代码加载并执行|
|目标|寻找活动分区|加载启动管理器 (GRUB/Bootmgr)

- **BIOS 服务的使用边界**：BIOS 服务仅在引导阶段（加载内核前）有效；一旦内核加载并重建中断机制，系统不再调用 BIOS 中断进行硬件访问，而是直接使用驱动程序。
- **CMOS 与 ROM 的功能差异**：ROM 存储固定的 BIOS 程序代码，断电不丢失；CMOS 存储可配置参数（启动顺序、时间），由电池供电维持，断电后若电池失效数据会丢失。
