# 1.7 本章疑难点

> [!abstract] 一句话总结
> 本节厘清并发与并行的时空差异，界定特权/非特权指令边界，阐明访管中断作为用户态进入内核态的唯一主动途径，并概括微内核 OS 的四大设计特征。

## 核心要点
### 考点1：并行性与并发性的区别
**并行性指多个事件在同一时刻发生，并发性指多个事件在同一时间间隔内发生。**
单处理器：宏观同时运行，微观分时交替；多处理器：可将并发程序分配至不同处理器实现真正并行。

> [!tip] 考试怎么用
> 注意区分'时刻'（瞬间）与'时间间隔'（时段），单 CPU 只能并发不能并行。

### 考点2：特权指令与非特权指令
**特权指令仅允许在内核态执行，用户态执行特权指令会触发异常，从用户态切换至内核态的唯一途径是中断或异常。**
特权指令操作：清内存、置时钟、分配资源、修改页表等；CPU 内核态可执行完整指令集，用户态仅执行非特权指令。

> [!tip] 考试怎么用
> 牢记'唯一途径'是中断或异常，用户程序无法直接切换状态，必须靠硬件触发。

### 考点3：访管指令与访管中断
**访管指令是用户态执行的特殊指令，用于主动引发访管中断（自愿中断），实现从用户态到内核态的切换以请求系统服务。**
机制：用户执行访管指令 $\to$ 产生自愿中断 $\to$ 切换至内核态 $\to$ 内核处理请求（如 I/O、进程创建）。

> [!tip] 考试怎么用
> 访管指令本身不是特权指令，它是用户态主动进入内核态的受控入口，区别于硬件故障引发的异常。

### 考点4：微内核结构的四个方面
**微内核 OS 具备足够小的内核、基于客户/服务器模式、机制与策略分离、采用面向对象技术四个特征。**
机制与策略分离：机制保留在内核，策略移至用户态服务进程；面向对象：利用抽象、封装、继承提升可靠性与扩展性。

> [!tip] 考试怎么用
> 重点记忆'机制在内核，策略在用户态'的分离思想，这是减小内核规模的关键。

## 易混与对比
**并行性 vs 并发性**

|维度|并行性 (Parallelism)|并发性 (Concurrency)|
|---|---|---|
|时间特征|同一**时刻**发生|同一**时间间隔**内发生|
|单 CPU 支持|不支持（微观交替）|支持（宏观同时，微观分时）|
|多 CPU 支持|支持（真正同时）|支持（分配至不同处理器）|

**特权指令 vs 访管指令**

|特性|特权指令|访管指令|
|---|---|---|
|执行状态|仅内核态|用户态|
|触发方式|直接执行（若非法则异常）|主动执行引发自愿中断|
|目的|执行关键系统操作（清内存等）|请求操作系统服务（系统调用）|
|是否特权|是|否|

**用户态切换内核态的途径**

|途径类型|具体方式|主动性|典型场景|
|---|---|---|---|
|被动切换|中断（外部事件）、异常（错误/非法）|被动（硬件触发）|时钟中断、除零错误、非法指令|
|主动切换|访管指令（Trap）|主动（程序执行）|系统调用（I/O 请求、文件操作）|
|结论|唯一途径统称为“中断或异常”，访管指令引发的是其中特殊的“自愿中断”。| | |

## 闪卡
#card
- 并行性的时间特征是什么？::多个事件在同一时刻发生。
- 并发性的时间特征是什么？::多个事件在同一时间间隔内发生。
- 单处理器系统中程序执行的微观表现？::分时交替执行，任一时刻仅执行一个程序。
- 多处理器如何实现真正的并行？::将并发执行的程序分配至不同处理器同时执行。
- 特权指令允许在什么状态下执行？::仅允许在内核态执行。
- 用户程序试图执行特权指令的后果？::硬件触发异常以阻止该操作。
- 从用户态切换至内核态的唯一途径？::中断或异常。
- CPU 在内核态下能执行哪些指令？::可执行完整的指令集（含特权与非特权指令）。
- 访管指令可以在哪种状态下执行？::可在用户态执行。
- 执行访管指令引发的中断类型？::自愿中断（访管中断）。
- 系统调用是通过什么指令实现的？::通过访管指令实现。
- 访管指令本身是否属于特权指令？::不是，它是为用户提供受控内核态入口的非特权指令。
- 微内核仅包含哪些核心功能？::进程间通信、基本调度等最基础功能。
- 微内核 OS 采用何种服务模式？::基于客户/服务器模式（内核为服务器，应用为客户端）。
- 微内核中机制与策略如何分布？::机制保留在内核中，策略移至用户态服务进程。
- 采用面向对象技术的主要目的？::控制复杂性，提升正确性、可靠性与可扩展性。
