# 2.1 进程与线程简介

> [!abstract] 一句话总结
> 进程是资源分配与动态执行的独立实体，线程是轻量级调度单元，二者通过 PCB/TCB 管理状态转换与资源共享。

## 核心要点
### 考点1：进程概念与特征
**进程是进程实体的运行过程，是系统进行资源分配和调度的一个独立单位。**
进程实体 = 程序段 + 数据段 + PCB；动态性、并发性、独立性、异步性。

> [!tip] 考试怎么用
> 区分静态程序与动态进程；PCB 是进程存在的唯一标志。

### 考点2：进程控制块 (PCB)
**PCB 是进程存在的唯一标志，系统唯有通过它才能感知并管理进程。**
PCB 内容：标识信息 (PID)、调度信息 (状态/优先级)、资源信息 (内存指针)、处理机状态 (寄存器/PC/PSW)。

> [!tip] 考试怎么用
> 进程切换本质是保存/恢复 PCB 中的处理机状态信息；PCB 常驻内存。

### 考点3：进程内存映像
**进程虚拟地址空间包含代码段、数据段、堆、栈及共享库映射区，PCB 位于内核区不属于用户空间。**
布局：低地址→代码段 (.text/.rodata)→数据段 (.data/.bss)→堆 (向上增长)→共享库→栈 (向下增长)←高地址。

> [!tip] 考试怎么用
> 区分 .data(已初始化) 与 .bss(未初始化)；堆栈增长方向相反；PCB 不在虚拟地址空间内。

### 考点4：进程状态与转换
**进程五态为创建、就绪、运行、阻塞、终止；就绪缺 CPU，阻塞缺事件/资源。**
转换：就绪$\to$运行 (调度)；运行$\to$就绪 (时间片完/抢占)；运行$\to$阻塞 (请求 I/O)；阻塞$\to$就绪 (事件发生)。

> [!tip] 考试怎么用
> 阻塞态不能直接转运行态；运行态转阻塞是主动行为，阻塞转就绪是被动行为。

### 考点5：进程控制原语
**进程控制通过原语实现，包括创建、终止、阻塞和唤醒，原语执行期间不可中断。**
创建：申请 PCB$\to$分配资源$\to$初始化$\to$插入就绪队列；终止：回收资源$\to$移除 PCB。

> [!tip] 考试怎么用
> 阻塞原语仅运行态进程可调用；唤醒原语由内核或其他进程调用；注意级联终止机制。

### 考点6：进程通信 (IPC)
**IPC 分为低级通信 (控制信息) 和高级通信 (大量数据)，后者含共享存储、消息传递、管道、信号。**
管道：固定大小内核缓冲区，半双工，满写阻塞/空读阻塞；信号：异步通知机制，内核/进程发送。

> [!tip] 考试怎么用
> 共享存储需用户自行同步；管道是一次性读取；信号处理可自定义或默认。

### 考点7：线程概念与比较
**线程是轻量级进程，是 CPU 调度的基本单位；进程是资源分配的基本单位。**
线程私有：TCB、寄存器、栈；线程共享：代码段、数据段、堆、文件描述符。

> [!tip] 考试怎么用
> 同进程内线程切换开销小（无地址空间切换）；线程切换可能触发进程切换（跨进程时）。

### 考点8：线程实现模型
**线程实现分用户级 (ULT)、内核级 (KLT) 及组合方式，映射模型有多对一、一对一、多对多。**
ULT：用户态管理，切换快但阻塞全挂；KLT：内核管理，支持并行但开销大；多对多兼顾两者。

> [!tip] 考试怎么用
> ULT 无法利用多核并行；KLT 一个线程阻塞不影响同进程其他线程。

## 易混与对比
**就绪态 vs 阻塞态**

|特征|就绪态|阻塞态|
|---|---|---|
|缺少资源|仅缺少 CPU|缺少除 CPU 外的资源或等待事件|
|转换主动性|被动被调度|主动请求 (运行→阻塞) / 被动唤醒 (阻塞→就绪)|
|发生频率|高频 (时间片轮转)|低频 (I/O 等长耗时操作)|
|能否直接运行|获得 CPU 即可运行|必须先转为就绪态|

**进程 vs 线程**

|维度|进程|线程|
|---|---|---|
|资源分配|基本单位 (拥有地址空间)|不拥有系统资源 (共享进程资源)|
|调度单位|传统 OS 是基本单位|现代 OS 是基本调度单位|
|开销|创建/切换/通信开销大|创建/切换/通信开销小|
|独立性|地址空间完全隔离|同进程线程共享地址空间，独立性弱|

**用户级线程 vs 内核级线程**

|特性|用户级线程 (ULT)|内核级线程 (KLT)|
|---|---|---|
|管理主体|用户态线程库|操作系统内核|
|阻塞影响|一线程阻塞，全进程阻塞|一线程阻塞，其他线程可运行|
|多核支持|不支持并行 (单核交替)|支持多核并行执行|
|切换开销|小 (无需模式切换)|大 (需陷入内核态)|

**共享存储 vs 消息传递**

|机制|共享存储|消息传递|
|---|---|---|
|数据交换方式|直接读写共享内存区|发送/接收格式化消息|
|同步责任|用户程序自行实现同步互斥|内核封装细节，隐含同步|
|效率|高 (无数据拷贝)|较低 (涉及内核拷贝)|
|适用场景|大数据量、高性能需求|分布式、微内核、安全性要求高|

## 闪卡
#card
- 进程最根本的特征是什么？::动态性，具有创建、就绪、运行、阻塞、终止的生命周期。
- 引入进程主要解决了什么问题？::多道程序并发执行中的封闭性破坏、间断性及结果不可再现问题。
- 进程与程序的本质区别？::程序是静态指令集合，进程是动态执行过程且拥有 PCB。
- 进程独立性的体现？::独立运行、独立获取资源、作为调度基本单位参与 CPU 竞争。
- PCB 中哪类信息用于恢复执行现场？::处理机状态信息，含通用寄存器、程序计数器、栈指针及 PSW。
- 创建进程的本质操作是什么？::申请并初始化一个空白的 PCB。
- PCB 的组织方式有哪些？::链接方式（就绪/阻塞队列）和索引方式（状态索引表）。
- 撤销进程时首先做什么？::回收该进程的 PCB 及相关资源。
- 未初始化的全局变量存放在哪？::.bss 段，属于数据段的一部分。
- 堆和栈的增长方向分别如何？::堆从低地址向高地址增长，栈从高地址向低地址扩展。
- PCB 存放在进程的虚拟地址空间中吗？::不存放，PCB 由内核维护，位于系统内核区。
- 字符串常量"Hello"存放在哪？::.rodata 段（只读数据段）。
- 运行态能否直接转换为阻塞态？触发条件？::能，进程主动发起系统调用（如 I/O 请求）且需等待时。
- 阻塞态能否直接转换为运行态？::不能，必须先转为就绪态，经调度后才能运行。
- 时间片用完导致的状态转换？::运行态$\to$就绪态。
- I/O 操作完成引发的状态转换？::阻塞态$\to$就绪态。
- 创建新进程的第一步操作？::分配唯一标识 (PID) 并从 PCB 池申请空白 PCB。
- 谁可以执行阻塞原语 (Block)？::只有处于运行态的进程才能主动调用阻塞原语。
- 唤醒原语 (Wakeup) 的主要动作？::将 PCB 从等待队列移出，状态置为就绪，插入就绪队列。
- 父进程终止时子进程一定终止吗？::不一定，取决于系统策略（如 Linux 中由 init 收养）。
- 管道通信中写进程何时阻塞？::当管道缓冲区满时，写进程自动阻塞。
- 共享存储机制中谁负责同步互斥？::用户程序自行设计实现，操作系统仅提供映射。
- 信号量属于哪种通信类型？::低级通信，主要用于传递控制信息（同步/互斥）。
- 普通管道支持双向通信吗？::不支持，仅单向；双向需创建两个管道。
- 线程拥有独立的地址空间吗？::不拥有，同一进程内线程共享地址空间。
- 线程切换比进程切换开销小的原因？::无需切换地址空间和大部分资源上下文，仅保存恢复寄存器和栈。
- 多线程进程在多核 CPU 上的优势？::多个线程可并行运行于不同核心，真正发挥多核性能。
- 线程私有的数据结构主要有哪些？::线程 ID、程序计数器、寄存器集合、栈指针。
- 用户级线程 (ULT) 的主要缺点？::一个线程阻塞导致整个进程阻塞，且无法利用多处理器并行。
- 一对一模型中创建线程的开销如何？::较大，每创建一个用户线程需对应创建一个内核线程。
- 多对多模型中 n 与 m 的关系？::$n \geq m$，n 个用户线程映射到 m 个内核线程。
- 哪种模型能同时实现高效切换和多核并行？::多对多模型（组合方式）。
