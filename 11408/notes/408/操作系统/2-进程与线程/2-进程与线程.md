# 进程与线程

> [!abstract] 一句话总结

## 核心考点
### 考点1：进程实体与状态机
**进程是资源分配的基本单位，由程序段、数据段和 PCB 构成，其生命周期在五种状态间动态转换。**
进程实体 = 程序段 + 数据段 + PCB；状态转换：就绪$\xrightarrow{调度}$运行$\xrightarrow{时间片完/抢占}$就绪；运行$\xrightarrow{I/O 请求}$阻塞$\xrightarrow{I/O 完成}$就绪。

> [!tip] 考试怎么用
> 区分就绪与阻塞的关键是缺 CPU 还是缺其他资源；注意创建态和终止态是过渡状态。

### 考点2：线程模型与实现
**线程是 CPU 调度的基本单位，同一进程内线程共享地址空间，切换开销远小于进程。**
用户级线程 (ULT)：内核不可见，切换快但阻塞全进程；内核级线程 (KLT)：内核管理，支持多核并行但切换慢；多对多模型结合两者优点。

> [!tip] 考试怎么用
> 牢记线程不拥有系统资源（除栈、寄存器等私有数据），多对一模型无法利用多核。

### 考点3：三级调度体系
**操作系统通过作业、中级、进程三级调度协同管理资源，其中进程调度频率最高且必不可少。**
高级调度（作业）：外存$\to$内存，创建进程；中级调度（内存）：挂起/激活，调节内存负载；低级调度（进程）：就绪$\to$运行，分配 CPU。

> [!tip] 考试怎么用
> 分时和实时系统通常无作业调度；中级调度对应存储管理的对换功能。

### 考点4：经典调度算法
**不同场景需选用不同算法：FCFS 公平但短作业不利，SJF 周转时间最优但易饥饿，RR 适合分时系统。**
SJF 平均等待时间最优；RR 时间片过大退化为 FCFS，过小增加开销；多级反馈队列兼顾长短作业，通用性最强。

> [!tip] 考试怎么用
> 计算周转时间$T = T_{完成} - T_{提交}$；注意 SJF 的饥饿问题和 RR 时间片选取原则。

### 考点5：临界区互斥实现
**临界区访问需遵循空闲让进、忙则等待、有限等待原则，硬件指令可保证原子性但可能忙等待。**
Peterson 算法满足前三条准则但忙等待；TestAndSet/Swap 指令利用硬件原子性实现互斥，适用于多处理器但违背让权等待。

> [!tip] 考试怎么用
> 软件方法（如 Peterson）不适用于多核；硬件方法（TS/Swap）会导致 CPU 浪费。

### 考点6：信号量机制与应用
**记录型信号量通过 wait/signal 原语实现让权等待，是解决同步互斥及经典问题的核心工具。**
wait(S): $S.value--$，若$<0$则阻塞；signal(S): $S.value++$，若$\leq 0$则唤醒。互斥初值 1，同步初值 0。

> [!tip] 考试怎么用
> 生产者 - 消费者中 P(empty) 必须在 P(mutex) 之前，否则死锁；读者 - 写者需计数器。

### 考点7：管程机制
**管程将共享资源及操作封装，自动保证互斥，利用条件变量实现同步，简化了编程复杂度。**
管程由共享数据结构、操作过程、初始化代码组成；条件变量 x.wait() 阻塞并释放管程，x.signal() 唤醒等待进程。

> [!tip] 考试怎么用
> 管程互斥由编译器/系统保证，程序员只需关注逻辑；条件变量无数值，仅用于排队。

### 考点8：死锁必要条件
**死锁发生必须同时满足互斥、不可剥夺、请求并保持、循环等待四个条件，破坏其一即可预防。**
预防策略：静态分配破坏请求并保持；有序分配破坏循环等待；资源剥夺破坏不可剥夺条件。

> [!tip] 考试怎么用
> 资源分配图有环不一定死锁（多实例时）；单实例时有环必死锁。

### 考点9：银行家算法与安全状态
**银行家算法通过试探性分配和安全性检查，确保系统始终处于安全状态以避免死锁。**
安全状态：存在安全序列使所有进程完成；算法步骤：检查请求合法性$\to$可用性$\to$试探分配$\to$安全性检测。

> [!tip] 考试怎么用
> 需熟练掌握 Need=Max-Allocation 计算及安全序列推导过程；不安全状态未必死锁。

### 考点10：死锁检测与解除
**允许死锁发生时，通过资源分配图化简检测死锁，采用剥夺、撤销或回退策略解除。**
死锁定理：资源分配图不可完全简化则死锁；解除方法：资源剥夺、撤销进程（代价高）、进程回退。

> [!tip] 考试怎么用
> 化简时找非阻塞进程（请求可满足），释放其资源后删除边，重复直至无法化简。

## 易混与对比
**进程 vs 线程**

|维度|进程 (Process)|线程 (Thread)|
|:---|:---|:---|
|**资源拥有**|系统资源分配的基本单位，拥有独立地址空间|不拥有系统资源，共享进程资源，仅有栈/寄存器|
|**调度单位**|传统 OS 中是调度单位，现代 OS 中不是|CPU 调度和执行的基本单位|
|**切换开销**|大，涉及地址空间、页表等切换|小，同一进程内只需切换寄存器/栈|
|**通信方式**|需 IPC 机制（共享内存、消息等）|可直接读写同一进程数据，效率高|
|**并发性**|进程间并发|进程内、进程间均可并发，支持多核并行|

**死锁 vs 饥饿**

|维度|死锁 (Deadlock)|饥饿 (Starvation)|
|:---|:---|:---|
|**涉及进程**|至少两个进程，形成循环等待链|可以是一个或多个进程|
|**产生原因**|资源竞争 + 推进顺序非法，满足四个必要条件|调度策略不公平（如长作业等待短作业）|
|**进程状态**|必定处于阻塞态，互相等待对方资源|可能是就绪态（等 CPU）或阻塞态（等资源）|
|**系统状态**|相关进程永久无法推进，需外部干预|系统仍在运行，其他进程可正常执行|
|**解决思路**|预防、避免、检测解除|改进调度算法（如老化技术提高优先级）|

**同步 vs 互斥**

|维度|同步 (Synchronization)|互斥 (Mutual Exclusion)|
|:---|:---|:---|
|**关系类型**|直接制约关系（协作），源于任务配合|间接制约关系（竞争），源于资源共享|
|**核心目的**|协调执行次序，保证前驱后继关系|保证临界资源同一时刻仅被一个进程访问|
|**信号量初值**|通常为 0（表示初始无资源/事件未发生）|通常为 1（表示资源初始可用）|
|**典型场景**|生产者生产后消费者才能消费|多个进程争用打印机或共享变量|
|**PV 操作位置**|P 在等待点前，V 在提供点后|P/V 成对夹住临界区代码|

**死锁预防 vs 死锁避免**

|维度|死锁预防 (Prevention)|死锁避免 (Avoidance)|
|:---|:---|:---|
|**策略性质**|静态策略，事先施加严格限制|动态策略，运行时判断安全性|
|**实现手段**|破坏四个必要条件之一（如有序分配）|银行家算法，检查分配后是否安全|
|**资源利用率**|较低，资源可能闲置|较高，允许更多并发请求|
|**实施难度**|简单，无须运行时检测|复杂，需预知最大资源需求|
|**典型应用**|一次性分配、资源有序编号|银行家算法（需已知 Max 矩阵）|

**用户级线程 vs 内核级线程**

|维度|用户级线程 (ULT)|内核级线程 (KLT)|
|:---|:---|:---|
|**管理主体**|用户空间线程库，内核不可见|操作系统内核，内核直接管理|
|**切换开销**|小，无需模式切换|大，需陷入内核态，上下文切换重|
|**阻塞影响**|一线程阻塞，全进程阻塞|一线程阻塞，其他线程可继续运行|
|**多核支持**|不支持，单进程只能占一个 CPU|支持，多线程可并行运行于多核|
|**适用场景**|频繁切换且无阻塞调用的计算任务|I/O 密集型或需真正并行的任务|

## 闪卡
#card
- 进程存在的唯一标志是什么？::进程控制块（PCB），系统通过 PCB 感知和管理进程。
- 进程从运行态转为阻塞态的原因是什么？::进程主动请求 I/O 或等待事件，因资源未就绪而主动放弃 CPU。
- 就绪态与阻塞态的本质区别？::就绪态仅缺 CPU，阻塞态缺除 CPU 外的其他资源或事件。
- PCB 中保存的 CPU 上下文包含哪些？::通用寄存器、程序计数器 PC、栈指针 SP、程序状态字 PSW。
- 线程与进程在资源拥有上的区别？::进程拥有独立地址空间和资源，线程共享进程资源，仅拥栈和寄存器。
- 用户级线程的主要缺点是什么？::一个线程阻塞会导致整个进程阻塞，且无法利用多处理器并行。
- 内核级线程切换为何开销大？::需从用户态陷入内核态，涉及完整的上下文保存恢复及 TLB 刷新。
- 多对多线程模型的特点？::n 个用户线程映射到 m 个内核线程，兼顾切换效率与多核并行。
- 哪一级调度在所有 OS 中都必须存在？::低级调度（进程调度），负责从就绪队列选择进程分配 CPU。
- 中级调度的主要作用是什么？::提高内存利用率，通过将进程挂起换出或激活换入来调节负载。
- 作业调度与进程调度的频率关系？::作业调度频率最低，进程调度频率最高（毫秒级）。
- 闲逛进程（Idle Process）的作用？::当无就绪进程时占用 CPU，优先级最低，防止 CPU 空转。
- 哪种算法平均周转时间理论上最优？::短作业优先（SJF），但可能导致长作业饥饿。
- 时间片轮转（RR）算法适合什么系统？::分时系统，通过公平分配时间片保证响应时间。
- 多级反馈队列如何避免长作业饥饿？::长作业虽降至低优先级队列，但仍能轮转获得 CPU，不会无限等待。
- 高响应比优先算法的公式？::$R_p = (等待时间 + 要求服务时间) / 要求服务时间$。
- Peterson 算法未遵循哪条准则？::让权等待，它在进入区采用忙等待循环测试。
- TestAndSet 指令的功能逻辑？::原子地读取锁旧值并置为 true，返回旧值以判断是否获取锁成功。
- 关中断法为何不适用于多处理器？::关中断仅影响当前 CPU，无法阻止其他 CPU 访问同一临界资源。
- 实现互斥的四个区域顺序？::进入区$\to$临界区$\to$退出区$\to$剩余区。
- 记录型信号量如何实现让权等待？::当$S.value < 0$时，调用 block 原语将进程阻塞并加入等待队列。
- 互斥信号量的初值通常设为多少？::1，表示临界资源初始可用数量为 1。
- 生产者 - 消费者中 P 操作的顺序？::先 P(empty/full) 申请资源，再 P(mutex) 进入临界区，防止死锁。
- 信号量 S=-3 的含义？::表示 1 个进程在临界区，3 个进程在等待队列中阻塞。
- 管程如何实现互斥访问？::任一时刻仅允许一个进程执行管程内的过程，由系统自动保证。
- 条件变量 x.wait() 执行后的动作？::将当前进程加入 x 等待队列，并自动释放管程占用权。
- 管程与进程的主要区别？::进程是主动执行实体，管程是被动调用的资源管理模块。
- 条件变量与信号量的核心差异？::信号量有整数值记录资源数，条件变量无数值仅用于线程同步等待。
- 死锁产生的四个必要条件？::互斥、不可剥夺、请求并保持、循环等待。
- 资源有序分配法破坏了哪个条件？::循环等待条件，规定进程按编号递增顺序请求资源。
- 静态资源分配策略的缺点？::资源利用率低，易导致饥饿，因为进程运行前需占用所有资源。
- 资源分配图中有环是否一定死锁？::否，仅当每类资源只有一个实例时，有环才是死锁的充要条件。
- 系统处于安全状态是否一定无死锁？::是，安全状态一定能找到安全序列，绝不会发生死锁。
- 银行家算法中 Need 矩阵的计算公式？::$Need[i,j] = Max[i,j] - Allocation[i,j]$。
- 安全性算法中 Work 向量的初始值？::等于当前系统的 Available 向量。
- 若系统处于不安全状态会发生什么？::死锁可能发生，但并非必然发生，取决于后续进程请求顺序。
- 死锁定理的核心内容？::系统死锁当且仅当资源分配图不可完全简化。
- 资源剥夺法解除死锁的风险？::可能导致被剥夺资源的进程陷入饥饿。
- 撤销进程法的主要代价？::进程已完成的工作丢失，需重新执行，开销较大。
- 死锁检测与避免的主要区别？::避免需预知最大需求并事前检查，检测仅依据当前状态事后发现。
