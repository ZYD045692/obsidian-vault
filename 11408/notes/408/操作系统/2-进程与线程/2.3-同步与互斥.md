# 2.3 同步与互斥

> [!abstract] 一句话总结
> 本节通过临界区准则、软硬件互斥算法及信号量/管程机制，解决并发进程间的直接制约（同步）与间接制约（互斥）问题。

## 核心要点
### 考点1：同步与互斥基本概念
**同步是直接制约关系源于合作，互斥是间接制约关系源于竞争临界资源。**
临界区访问四部分：进入区 (entry) → 临界区 (critical) → 退出区 (exit) → 剩余区 (remainder)。

> [!tip] 考试怎么用
> 区分直接制约（同步，如 A 等 B 结果）与间接制约（互斥，如 A 等 B 用完打印机）。

### 考点2：临界区调度准则
**同步机制需遵循空闲让进、忙则等待、有限等待三条强制准则，让权等待为理想准则。**
四条准则：1.空闲让进 2.忙则等待 3.有限等待 4.让权等待（避免忙等待）。

> [!tip] 考试怎么用
> Peterson 算法和硬件指令法通常不满足“让权等待”，因为它们使用忙等待循环。

### 考点3：软件互斥算法
**单标志法违背空闲让进，双标志先检查违背忙则等待，双标志后检查违背空闲让进，Peterson 算法完善但忙等待。**
Peterson 算法核心：$flag[i]=true; turn=j; while(flag[j] \&\& turn==j);$。

> [!tip] 考试怎么用
> 重点掌握 Peterson 算法如何解决饥饿（通过 turn 变量谦让）及为何不满足让权等待。

### 考点4：硬件互斥方法
**中断屏蔽不适用于多处理器，TS 和 Swap 指令利用原子操作实现互斥但均存在忙等待缺陷。**
TS 指令逻辑：$while(TestAndSet(\&lock));$；Swap 指令逻辑：$while(key) Swap(\&lock, \&key);$。

> [!tip] 考试怎么用
> TS 和 Swap 指令由硬件保证原子性，适用于多处理器，但缺点是忙等待和可能饥饿。

### 考点5：记录型信号量机制
**记录型信号量通过 value 计数和等待队列 L 实现资源管理与让权等待，P/V 操作必须成对。**
wait(S): $S.value--$; if $S.value<0$ block(); signal(S): $S.value++$; if $S.value\leq0$ wakeup()。

> [!tip] 考试怎么用
> S.value 初值为资源数；互斥时初值 1，同步时初值 0；P/V 顺序颠倒易致死锁。

### 考点6：生产者 - 消费者问题
**需设置互斥信号量 mutex 和两个计数信号量 empty/full，P 操作顺序必须是先资源后互斥。**
Producer: $P(empty) \to P(mutex) \to \dots \to V(mutex) \to V(full)$；Consumer: $P(full) \to P(mutex) \to \dots \to V(mutex) \to V(empty)$。

> [!tip] 考试怎么用
> 若先 P(mutex) 再 P(empty)，当缓冲区满/空时，持有锁的进程阻塞，导致死锁。

### 考点7：读者 - 写者问题
**读者优先通过 count 计数器实现多读互斥写，写者优先需增加 w 信号量阻止新读者插队。**
读者优先核心：$if(count==0) P(rw); count++; \dots count--; if(count==0) V(rw);$。

> [!tip] 考试怎么用
> 写者优先策略中，读者和写者进入前都需 P(w)，以阻止新读者在写者等待时进入。

### 考点8：管程机制
**管程封装共享数据与操作，自动保证互斥，利用条件变量实现同步，进程被动调用管程过程。**
条件变量操作：$x.wait()$（阻塞并释放管程），$x.signal()$（唤醒一个等待进程）。

> [!tip] 考试怎么用
> 管程互斥由编译器/系统保证，无需程序员写 P/V；条件变量无数值，仅用于排队。

## 易混与对比
**同步与互斥的区别**

|特征|同步 (Synchronization)|互斥 (Mutual Exclusion)|
|:---|:---|:---|
|**制约关系**|直接制约（协作关系）|间接制约（竞争关系）|
|**产生原因**|进程间需要协调执行次序|多个进程竞争同一临界资源|
|**典型场景**|生产者生产后消费者才能消费|多个进程争用打印机|
|**信号量初值**|通常为 0（表示事件未发生）|通常为 1 或资源总数|
|**核心目的**|保证执行顺序正确|保证资源访问独占性|

**忙等待与让权等待**

|机制类型|代表算法/指令|是否忙等待|是否让权等待|CPU 利用率影响|
|:---|:---|:---|:---|:---|
|**软件算法**|单标志、双标志、Peterson|是|否|低（循环测试占用 CPU）|
|**硬件指令**|TestAndSet, Swap|是|否|低（适用于多核短临界区）|
|**中断屏蔽**|关中断|否（阻塞切换）|是|极低（禁止并发）|
|**记录型信号量**|wait/signal (含 block)|否|是|高（阻塞让出 CPU）|
|**管程**|condition.wait|否|是|高（自动阻塞释放）|

**死锁风险点：P 操作顺序**

|场景|需保护对象|信号量设置|
|:---|:---|:---|
|**读者计数**|变量 count 的增减操作|互斥信号量 mutex (初值 1)|
|**文件访问**|文件本身（读写互斥）|互斥信号量 rw (初值 1)|
|**写者优先**|进入权限（防插队）|互斥信号量 w (初值 1)|
**注意**：count 的修改必须在 mutex 保护下，但 P(rw) 仅在 count==0 时执行，且需在 mutex 保护范围内判断。

## 闪卡
#card
- 什么是临界资源？::一次仅允许一个进程访问的资源，如打印机或共享变量。
- 临界区是指什么？::进程中访问临界资源的那段代码。
- 同步关系的本质是什么？::为完成共同任务，进程间协调执行次序的直接制约关系。
- 互斥关系的本质是什么？::进程竞争临界资源，一方使用时另一方必须等待的间接制约关系。
- 临界区访问过程的四个部分顺序？::进入区、临界区、退出区、剩余区。
- “空闲让进”准则的含义？::临界区空闲时，请求进入的进程应立即被允许进入。
- “忙则等待”准则的含义？::已有进程在临界区时，其他试图进入的进程必须等待。
- “有限等待”准则的含义？::保证任何请求进程在有限时间内能进入临界区，避免饥饿。
- “让权等待”准则的要求？::进程无法进入临界区时应主动放弃 CPU 转为阻塞态，而非忙等待。
- 违背“有限等待”会导致什么现象？::饥饿现象，即进程长期或永远无法获得访问权。
- 单标志法的主要缺点？::强制交替进入，若一方不请求，另一方也无法再次进入（违背空闲让进）。
- 双标志先检查法的问题？::检查与设置非原子，可能导致两进程同时进入临界区（违背忙则等待）。
- 双标志后检查法的问题？::双方都设标志后互相等待，导致死锁且临界区空闲（违背空闲让进）。
- Peterson 算法中 turn 变量的作用？::当双方同时请求时，通过谦让机制决定谁优先，解决饥饿问题。
- Peterson 算法是否满足让权等待？::不满足，因为它在进入区使用 while 循环进行忙等待。
- 关中断方法为何不适用于多处理器？::某 CPU 关中断无法阻止其他 CPU 上的进程并发访问同一临界区。
- TestAndSet 指令的功能？::原子地读取锁旧值并置锁为 true，返回旧值以判断是否获取成功。
- Swap 指令实现互斥的原理？::原子交换锁变量与局部变量，若局部变量获旧值 false 则成功进入。
- 硬件指令法共同的缺点？::等待进程持续执行指令形成忙等待，浪费 CPU 且不满足让权等待。
- TS 指令相比关中断的优势？::基于共享变量，适用于多处理器系统。
- 记录型信号量中 value<0 的含义？::表示资源已分配完，绝对值为等待队列中的进程数。
- wait 操作中何时调用 block 原语？::当 S.value 减 1 后小于 0 时，进程自我阻塞并加入等待队列。
- signal 操作中何时调用 wakeup 原语？::当 S.value 加 1 后小于等于 0 时，唤醒等待队列中的一个进程。
- 实现互斥时信号量初值设为多少？::1，表示临界资源初始可用数量为 1。
- 实现同步时信号量初值设为多少？::0，表示初始时所需资源或条件尚未满足。
- 生产者 - 消费者问题中 empty 信号量初值？::n，表示缓冲区中空位的数量。
- 生产者 - 消费者问题中 full 信号量初值？::0，表示缓冲区中已有产品的数量。
- 为何 P(empty) 必须在 P(mutex) 之前？::防止进程持有互斥锁时因资源不足阻塞，导致其他进程无法释放资源而死锁。
- 若缓冲区容量为 1，需要几个信号量？::3 个：1 个互斥信号量，2 个同步信号量（empty 和 full）。
- 消费者进程最后执行什么 V 操作？::V(empty)，表示消费后产生了一个空缓冲区。
- 读者 - 写者问题中 count 变量的作用？::记录当前正在读文件的读者数量，用于判断是否是第一个或最后一个读者。
- 读者优先策略可能导致什么问题？::写者饥饿，即写者因读者源源不断而长期无法获得访问权。
- 实现写者优先需增加什么信号量？::增加互斥信号量 w，用于控制进入“准备访问”阶段的权限。
- 写者优先策略中读者何时执行 V(w)？::在更新 count 后立即执行 V(w)，以便让等待的写者有机会竞争，但已读读者继续。
- 第一个读者进入时执行什么特殊操作？::执行 P(rw)，阻塞写者，确保读期间无写者介入。
- 管程的互斥性由谁保证？::由管程机制本身（编译器或系统）自动保证，任一时刻仅一个进程执行管程过程。
- 条件变量 x.wait() 执行后的动作？::将进程加入 x 等待队列，并自动释放管程占用，允许其他进程进入。
- 条件变量与信号量的主要区别？::信号量有整数值记录资源数，条件变量无数值仅用于线程排队和通知。
- 管程中进程如何访问共享资源？::必须通过调用管程内定义的过程（函数），不能直接访问内部数据。
- x.signal() 操作的效果？::唤醒一个因等待条件变量 x 而阻塞的进程，若无等待进程则无操作。
