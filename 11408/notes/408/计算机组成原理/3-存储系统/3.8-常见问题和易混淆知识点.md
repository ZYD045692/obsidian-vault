# 3.8 常见问题和易混淆知识点

> [!abstract] 一句话总结
> Cache 行长需在空间局部性收益与缺失代价、映射灵活性损失之间寻找平衡，且取指缺失需保持 PC 不变以支持重取。

## 核心要点
### 考点1：Cache 行长与命中率的关系
**Cache 行较大有利于利用空间局部性提高命中率，但过大会增加缺失损失并降低地址映射灵活性。**
行长过大后果：①缺失损失增加（传输时间更长）；②行数减少导致映射灵活性降低。

> [!tip] 考试怎么用
> 注意辩证分析：并非行越大越好，需考虑总容量固定时行数减少对冲突率的影响。

### 考点2：取指令 Cache 缺失的处理过程
**取指缺失时需保持程序计数器不变，从主存读取指令并调入 Cache，更新标记后重新取指。**
处理步骤：1) 保持 PC 不变；2) 按 PC 地址从主存读指令；3) 调入 Cache 并更新有效位和标记位；4) 重新取指执行。

> [!tip] 考试怎么用
> 关键易错点是第一步必须保持 PC 不变，否则无法重新获取同一条指令。

## 易混与对比
**Cache 行长选择的权衡矛盾**

|维度|行长较大|行长较小|
|---|---|---|
|空间局部性|利用更好，命中率倾向提高|难以有效利用，命中率倾向偏低|
|缺失损失|增加（传输时间更长）|较小|
|映射灵活性|降低（行数减少，易冲突）|较高（行数多）|
|结论|不宜过大，需平衡利弊|过小导致命中率低

## 闪卡
#card
- Cache 行较大时提高命中率的主要原理是什么？::更好利用空间局部性，一次性调入更多相邻数据。
- Cache 行长过大导致的第一个主要负面影响是什么？::增加缺失损失，未命中时从主存读取数据传输时间更长。
- 在总容量固定时，Cache 行长增大会如何影响地址映射？::导致行数减少，降低地址映射灵活性，可能降低命中率。
- Cache 行长过小对命中率有何影响及原因？::命中率通常偏低，因为难以有效利用空间局部性。
- 发生取指令 Cache 缺失时，程序计数器（PC）应如何变化？::保持 PC 不变，确保缺失处理完成后能重新获取同一条指令。
- 取指缺失处理中，从主存读取数据的依据地址是什么？::根据程序计数器（PC）指向的地址从主存读取该指令。
- 将主存块调入 Cache 后，必须更新哪两个关键位？::更新对应 Cache 行的有效位和标记位。
- 取指缺失处理完成的最后一步操作是什么？::重新从 Cache 中取指并继续执行。
