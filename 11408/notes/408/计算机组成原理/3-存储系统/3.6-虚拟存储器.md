# 3.6 虚拟存储器

> [!abstract] 一句话总结
> 虚拟存储器通过软硬协同将辅存映射为逻辑大内存，利用局部性原理和页表机制解决容量瓶颈，但需权衡缺页异常带来的巨大性能开销。

## 核心要点
### 考点1：虚拟存储器基本概念与回写策略
**虚拟存储器利用主存和辅存构建逻辑连续的大地址空间，仅在被置换且页面被修改（脏页）时才写回辅存以降低 I/O 开销。**
写回策略：页面被修改时标记为脏位，仅当该页被置换出主存且脏位为 1 时才写回辅存。

> [!tip] 考试怎么用
> 牢记虚拟存储器只能采用回写法，因为辅存速度慢，同步写不可行；缺页时若主存满需按替换算法置换。

### 考点2：页式虚拟存储器与页表结构
**页式存储以固定大小页为单位，页表项包含有效位、物理页号（或外存地址）、脏位和引用位，用于地址映射和替换算法。**
页表项结构：有效位 (1=在主存), 物理页号/外存地址，脏位 (1=已修改), 引用位 (1=已访问)。

> [!tip] 考试怎么用
> 有效位为 0 触发缺页异常；脏位决定置换时是否写回；引用位用于 LRU/Clock 算法；注意内部碎片问题。

### 考点3：页式地址转换过程
**虚拟地址分为虚页号和页内偏移，通过页表将虚页号映射为物理页号，再与不变的页内偏移拼接形成物理地址。**
转换步骤：1. 提取虚页号；2. 查页表得物理页号；3. 拼接页内偏移：$物理地址 = 物理页号 \times 页大小 + 页内偏移$。

> [!tip] 考试怎么用
> 页内偏移在虚实地址中完全一致；若有效位为 0 则中断；注意页表基址寄存器的作用。

### 考点4：快表 (TLB) 原理与多级存储
**TLB 是页表项的高速缓存，采用全相联或组相联映射，命中时直接获取物理页号，避免访问主存页表。**
TLB 命中：直接得物理页号；TLB 缺失：访问主存页表并装入 TLB（若满则替换）。

> [!tip] 考试怎么用
> TLB 缺失不一定缺页；Page 缺失则 TLB 必缺失；Cache 缺失由硬件处理，缺页由 OS 处理。

### 考点5：TLB、Page、Cache 缺失组合分析
**三种缺失存在逻辑依赖：Page 缺失必导致 TLB 和 Cache 缺失；TLB 命中则 Page 必命中。**
组合逻辑：$Page\ Miss \implies TLB\ Miss \land Cache\ Miss$；$TLB\ Hit \implies Page\ Hit$。

> [!tip] 考试怎么用
> 掌握表 3.3 的五种组合，特别是第 5 种（全缺失）需访磁盘且至少两次访主存；第 1 种最快。

### 考点6：段式与段页式虚拟存储器
**段式按逻辑划分，地址为段号 + 段内地址，有外部碎片；段页式结合两者，先分段再分页，地址为段号 + 页号 + 页内地址。**
段式物理地址：$起始地址 + 段内地址$（需检查段长）；段页式需两次查表（段表→页表）。

> [!tip] 考试怎么用
> 段式对程序员不透明（需考虑分段），有外部碎片；段页式开销大（两次查表）但无外部碎片。

### 考点7：虚拟存储器与 Cache 的比较
**两者都基于局部性原理，但 Cache 解决速度差异且全硬件实现，虚存解决容量问题且软硬协同，缺页开销远大于 Cache 缺失。**
关键差异：Cache 缺失延迟数十倍（访主存）；缺页延迟十万倍（访磁盘）；CPU 不直接访问辅存。

> [!tip] 考试怎么用
> 区分透明对象：Cache 对所有程序员透明；虚存对应用透明但对 OS 不透明；交换单位大小不同。

## 易混与对比
**TLB 缺失与缺页异常的逻辑关系**

|场景|TLB 状态|Page 状态|原因说明|
|---|---|---|---|
|页面在主存|可能命中或缺失|命中|TLB 只是缓存，未命中可查慢表|
|页面不在主存|必然缺失|缺失|页面不在主存，页表项无效，TLB 不可能缓存无效项|
|结论|**Page Miss $\implies$ TLB Miss**|**TLB Hit $\implies$ Page Hit**|反之不成立：TLB Miss 不一定 Page Miss|

**段式与页式的碎片类型对比**

|特性|页式虚拟存储|段式虚拟存储|
|---|---|---|
|划分单位|固定大小页|可变长度段|
|碎片类型|**内部碎片**（最后一页不满）|**外部碎片**（段间空闲区太小）|
|程序员视角|透明（无需关心）|不透明（需按逻辑分段）|
|共享保护|较难（缺乏逻辑意义）|容易（按逻辑段共享）|

**写回策略的触发条件**

|操作类型|Cache (通常)|虚拟存储器|
|---|---|---|
|写策略|可有直写或回写|**只能采用回写**|
|写回时机|替换或特定周期|**仅当页面被置换且脏位=1**|
|原因|主存速度尚可接受|辅存（磁盘）极慢，同步写不可行|

## 闪卡
#card
- 虚拟存储器中为何必须采用回写策略而非直写？::辅存访问延迟极高，每次写操作同步更新辅存不可行，仅置换脏页时写回可显著降低 I/O 开销。
- 页面被置换出主存时，什么条件下需要写回磁盘？::仅当该页面的脏位（修改位）为 1，表示页面在主存中被修改过。
- 虚拟存储器对应用程序员是否透明？对操作系统开发者呢？::对应用程序员透明（无须关心物理位置），对操作系统开发者不透明（需管理页表和置换）。
- 虚地址空间与实地址空间的大小关系通常如何？::虚地址空间远大于实地址空间，逻辑上连续但物理上分散。
- 页表项中有效位为 0 表示什么？系统如何响应？::表示该虚页未调入主存，CPU 访问时触发缺页异常，由操作系统调入页面。
- 页式虚拟存储器的主要缺点是什么？::最后一页产生内部碎片；页是物理划分，缺乏逻辑意义，不利于模块化保护和共享。
- 页表项中的引用位主要服务于什么功能？::记录页面是否被访问过，主要用于实现基于使用历史的页面替换算法（如 Clock 或 LRU）。
- 页式存储中，虚页能否装入主存任意位置？这类似哪种映射？::可以装入任意空闲页框，类似于全相联映射，提高了主存利用率。
- 虚拟地址到物理地址转换中，哪部分保持不变？::页内偏移（低位）完全一致，仅高位虚页号转换为物理页号。
- 地址转换时，若页表项有效位为 1，下一步做什么？::取出物理页号，与虚拟地址中的页内偏移拼接，形成最终物理地址。
- 页表存放在哪里？由什么寄存器指向其起始地址？::页表常驻主存，由页表基址寄存器指向当前进程页表的起始地址。
- 缺页异常处理完成后，必须更新哪个数据结构？::必须更新页表中的相应项（将有效位置 1 并填入物理页号）。
- TLB 命中但 Cache 缺失时，需要访问几次主存？::需要访问一次主存（读取数据并装入 Cache），无需查页表。
- 若发生缺页异常（Page Miss），TLB 状态必然如何？::TLB 必然缺失，因为页面不在主存，其页表项也不可能在 TLB 中。
- TLB 采用全相联映射时，标记字段是什么？::标记字段为完整的虚拟页号，需与所有 TLB 项并行比较。
- TLB 缺失的处理方式有哪些？::既可用硬件自动处理，也可由软件（操作系统）介入处理。
- 是否存在 TLB 命中但 Page 缺失的情况？为什么？::不存在。TLB 是页表项缓存，Page 缺失意味着页表项无效，TLB 不可能命中。
- 最坏的访存组合是哪一种？涉及哪些设备访问？::TLB、Page、Cache 均缺失；需访问磁盘调入页面，更新页表和 TLB，再访问主存取数据。
- TLB 缺失但 Page 命中时，需要访问几次主存才能取到数据（假设 Cache 也缺失）？::需要访问两次主存：第一次查页表获取物理地址，第二次访问数据。
- Cache 缺失和缺页异常分别由谁处理？::Cache 缺失由硬件自动完成；缺页异常由操作系统通过缺页处理程序实现。
- 段式虚拟存储器中，分段对程序员是否透明？::不透明。段是程序逻辑结构决定的，程序员编写程序时需考虑段的划分。
- 段式存储器的主要缺点是什么？::段长可变导致主存分配困难，段间容易产生外部碎片，造成存储空间浪费。
- 段页式地址变换过程中需要查几次表？::需要两次查表：先用段号查段表得页表始址，再用页号查页表得实页号。
- 段页式存储以什么为单位进行主存的调入和调出？::仍以页为基本交换单位，尽管逻辑上是分段管理的。
- Cache 缺失和缺页异常对系统性能影响的量级差异？::Cache 缺失延迟增加数十倍（访主存）；缺页延迟增加可达十万倍（访磁盘）。
- CPU 能否直接访问辅存中的数据？::不能。辅存与 CPU 无直接通路，缺页时必须先将数据从辅存调入主存。
- 虚拟存储器和 Cache 在实现方式上的根本区别？::Cache 完全由硬件实现；虚拟存储器由操作系统和硬件共同实现。
- 两者的基本交换单位大小关系如何？::虚拟存储器的页通常比 Cache 的块大得多。
