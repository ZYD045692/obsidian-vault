# 5.8 本章小结

> [!abstract] 一句话总结
> 指令与数据靠 CPU 时序区分，性能提升依赖时钟周期细分与流水线重叠执行。

## 核心要点
### 考点1：指令与数据的区分机制
**内存无法区分指令和数据，区分完全依赖 CPU 在不同工作阶段的控制信号引导流向。**
时间区分：取指阶段取指令，执行阶段取操作数；空间区分：取指阶段送指令寄存器 (IR)，执行阶段送通用寄存器/ALU。

> [!tip] 考试怎么用
> 选择题常考'内存能否区分'，答案必须是否定的；需明确区分依据是'CPU 阶段'而非内容本身。

### 考点2：指令周期与时钟周期
**指令周期是完成一条指令的总时间，其包含的时钟周期数取决于 CPU 是单周期还是多周期结构。**
单周期 CPU：$T_{指令} = T_{时钟}$；多周期 CPU：$T_{指令} = \sum T_{时钟}$ (包含多个节拍)。

> [!tip] 考试怎么用
> 注意区分单周期和多周期定义，严禁认为指令周期永远等于多个时钟周期。

### 考点3：微指令与机器指令关系
**微指令是微程序控制的基本单元，一条机器指令对应一个由多条微指令组成的微程序。**
层次关系：微命令 $\to$ 微指令 $\to$ 微程序 $\to$ 机器指令；一条微指令可并行发出多个微命令。

> [!tip] 考试怎么用
> 理清'微命令、微指令、微程序、机器指令'四层包含关系，常考对应数量关系（1 对多）。

### 考点4：指令流水线原理与优势
**流水线通过阶段重叠执行提升吞吐率，但不缩短单条指令的执行延迟。**
机制：各阶段专用部件，前令进下段、后令进当前段；效果：吞吐率显著提升，单条延迟不变。

> [!tip] 考试怎么用
> 核心陷阱：流水线提高的是'单位时间指令数'，而非'单条指令速度'，二者概念不同。

## 易混与对比
**指令周期与时钟周期的数量关系**

|CPU 类型|关系描述|公式表达|
|:---|:---|:---|
|单周期 CPU|指令周期等于时钟周期|$T_{指令} = T_{时钟}$|
|多周期 CPU|指令周期包含多个时钟周期|$T_{指令} > T_{时钟}$|

**流水线性能指标误区**

|指标|非流水线|流水线|变化结论|
|:---|:---|:---|:---|
|单条指令延迟|$T$|$T$|不变（易错点）|
|吞吐率 (IPS)|低|高|显著提升（核心优势）|

**控制单元层级对应关系**

|层级|组成单元|对应关系|
|:---|:---|:---|
|机器指令层|机器指令|1 条机器指令 $\leftrightarrow$ 1 个微程序|
|微程序层|微指令|1 个微程序 $\leftrightarrow$ 多条微指令|
|微指令层|微命令|1 条微指令 $\leftrightarrow$ 多个并行微命令|

## 闪卡
#card
- 内存本身能否区分存储的是指令还是数据？::不能，二者均以二进制形式共存，内存无法区分。
- 计算机如何在时间上区分指令和数据？::取指阶段取出的是指令，执行阶段取出的是操作数。
- 取指阶段读出的内容被送至哪个部件？::锁存至指令寄存器 (IR) 供译码。
- 执行阶段读出的数据流向哪里？::写入通用寄存器并送入 ALU 进行运算。
- 指令周期的定义是什么？::CPU 从内存取指并完成执行所需的全部时间。
- 时钟周期在 CPU 时序中的地位？::主时钟的一个节拍，是 CPU 操作最基本的时序单位。
- 单周期 CPU 中指令周期与时钟周期的关系？::指令周期恰好等于一个时钟周期。
- 多周期 CPU 中指令周期与时钟周期的关系？::指令周期包含多个时钟周期。
- 微指令在控制方式中的定位？::微程序控制方式中的基本控制单元。
- 微命令与微指令的构成关系？::一组完成特定微操作的微命令构成一条微指令。
- 一条机器指令对应多少个微程序？::通常对应一个微程序。
- 一个微程序由什么组成？::由若干条按序排列的微指令组成。
- 一条微指令能发出多少个微命令？::可并行发出多个微命令。
- 指令流水线的核心执行特征？::将指令划分为有序阶段，让多条指令的各阶段在时间上重叠执行。
- 流水线技术是否缩短了单条指令的执行延迟？::不缩短，单条指令执行延迟保持不变。
- 流水线相对于非流水线结构的主要优势？::显著提升单位时间内完成的指令数（吞吐率）。
- 实现流水线硬件代价的主要来源？::仅需增加少量流水线寄存器等硬件。
